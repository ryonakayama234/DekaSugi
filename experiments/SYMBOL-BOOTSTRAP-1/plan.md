## 授権と分割

Issue #227 の提案 6949460097、固定案 6949721000、Owner GO 6949870568 を実装する。正本は [lock.json](lock.json)。学習18本を台帳順に3巡、54 episode。a=4 / b1=4 / b2=2 / c=4、7文字自由生成、各試験は学習終了状態から独立、prefixによる学習なし。分類・期待値・作成側要素は学習器へ渡さない。単なる生文字列とepisode IDだけを渡す。

## 実装者が与える有限な帰納バイアス

1. FULLは各episodeの全連続部分文字列（長さ2〜8）を集計、異なる元文字列2件以上で記号candidateにする。新しい記号の展開は観測した文字に限定。前episodeまでの記号を最長一致で分割して、より長い記号の構成要素とする。依存は作成時に記録し、後付けしない。
2. 規則形成は既観測の異なる2文字列を、全ての同じ文字位置（1〜末尾手前）でprefix/suffixへ分けて行う。prefixの文字列、またはFULLのみの既獲得記号によるtoken列を位置対応で比較する。長さの等しいtoken列の差分の連続区間を最大2変数へ置換し、共通区間はliteralにする。変数は入力順にV0,V1。各変数の文字展開は1〜6、input literalは計8文字まで。
3. suffixは2例の両方に合う、束縛変数のコピー（最大4回）と観測literal（計8文字まで）の連結を有限列挙する。出力最大16 atom / 展開32文字。特定の語・区切り・並び替え規則は学習コードに埋め込まない。境界位置と候補文法そのものは与えたバイアスであり、自発的な言語の創造とは呼ばない。
4. 規則の支持・反例は、それをprefixに適用できる全既観測文字列について記録。1文字列の異なる束縛のうち少なくとも1つが残り全体に一致すれば支持、適用可能だが一致がなければ反例。元文字列のunique件数と反復episode数を別々に数える。新候補は過去に遡って検査し、後続の反例でもconfidenceを下げる。2つ以上の異なる元文字列の支持を予測利用条件とする。
5. FULLとNO-CHUNKは同じcharacter経路、原始的な束縛・照合・連結、文字展開上限・候補上限を共有する。NO-CHUNKは最初から別に54本を学習し、chunk作成・利用とsymbol経路を持たない。FULLのsymbol経路は同じ上限の中で追加費用を消費する。両者が並ぶ可能性を残す。
6. 予測は固定rankの適用可能規則を選び、出力列を左から7文字消費する（不足分は共通fallback、超過分は7文字で止め、全展開はtraceに残す）。一致する規則がなければMEMORYと同じprefix記憶／ngram。NO-LEARNは未観測alphabetの最小文字。同率順・保持・計算上限はlockのselection/limitsそのもの。

## 結果と解釈

分類別・b合算で7文字完全一致件数、FULL対各対照の勝ち/負け/同点、全56行、学習履歴（観測前予測、候補の増減・支持反例変化）、記号/規則の全状態、b全armの経路を保存する。bの来歴に学習episode ID・半開文字位置・形成時点・依存・束縛・fallback・競合・外れを含める。試験前後状態digestを検査。aのみ改善なら反復記憶効果。bでNO-CHUNK/MEMORYが同程度ならchunk寄与未確認。FULLが3対照よりよく来歴も整合した時のみ、この固定人工例での寄与所見。b1/b2を混同しない。cの成功は未知内容への適用経路として記録。統計的検定・日本語能力・意味理解・正式汎化能力は主張しない。結果後の例・上限調整はしない。
