## 0. 主張と認定上限

- 主主張（認定上限 B）: 同一 meta-runtime・同等の公開情報と学習/探索資源のもとで、経験から獲得した述語・二階スキーマを用いる学習器は、強い固定対照より未見法則 family に対する経験効率が高い。
- 補助主張（A）: 獲得した表現により seed の H0 では到達できなかった合法な解法が到達可能になる場合がある。主判定には使わない。
- 認定は3段: (i) 学習由来の新記号の系譜と実行可能性、(ii) 同一 snapshot・同一公開状態での USE ON/OFF の合法な行動差、(iii) 強い対照を上回る未見 family での有効性。いずれか未成立なら主張はその段に留める。
- 主評価は経験効率であり wall は主エンドポイントにしない（費用はベクトルとして個別記帳）。独立単位は生成法則 family であり、行動ステップや同一法則の複数事例を独立標本として数えない。
- G1/G2 の結果のみで Editor→Form 転移は認定しない（G3 は別事前登録）。

## 1. 世界 v0（テキストエディタ）

- 文字: 4記号 A/B/C/D。G1 の改名は「新しい不透明トークンへの一対一改名」として事前に定義し、観測・INSERT の実装は名称をハードコードしない。
- 状態: buffer（初期長 4〜12、上限 16）、cursor、selection（anchor/head または none、半開区間）、clipboard。完全観測・決定的。
- 原子行動（操作種として11種）: MOVE_LEFT / MOVE_RIGHT / INSERT(symbol) / DELETE_BACK / DELETE_RIGHT / SET_ANCHOR / EXTEND_LEFT / EXTEND_RIGHT / COPY / PASTE / CLEAR_SELECTION。意味名付きマクロは与えない。実際の分岐数（INSERT の記号インスタンスを含む）は別途監査する。
- 機械可読な行動契約を凍結前に全列挙する: 各行動の事前条件、無効時の扱い（no-op とし失敗とは数えない。ただし no-op にも原始呼出として課金し、ホライズン上限を設ける）、selection/clipboard の境界、容量、undo なし、終了規則。
- インターフェース: reset / observe / legal_actions / step。意味カテゴリへの対応表は学習側に渡さない。採点は独立 verifier のみが行う。

## 2. 課題の提示（goal contract）と識別可能性

- public goal contract は3要素: (i) 不透明な安定 task tag（法則・生成 seed・正解語彙を符号化しない）、(ii) 同一法則の別インスタンスに対する公開デモンストレーション対（初期状態→目標状態）を少数、経験予算へ課金して提示、(iii) 試行ごとの成功/失敗フィードバック。
- 真の target buffer・hidden rule・正解列は verifier のみに置く。評価時の再学習は0とし、評価フィードバックは監査専用で学習へ戻さない。
- 課題族: 転写、反復コピー、観測依存編集、2段連結の4族。分岐の最小証人は「同一公開課題条件で、共通の開ループ行動列では同時成功できず、かつ公開観測で条件分岐できる」対照ペアとする。
- 分割単位は意味生成法則の連結成分とし、同じ親法則の派生物が train と holdout を跨がないようにする。G1/G2 で同一 family を再利用する場合は独立な2標本とみなさず関連を記帳する。
- 識別可能性検査（校正時、§7）: 予算内で到達可能な公開履歴の同値類を列挙し、異なる必要行動を要求する2法則が全履歴で同値なら UNIDENTIFIABLE として当該課題設計を STOP/REDESIGN する。到達可能な公開証人の存在を family 採用の必要条件とする。ID-only の予測対照を置き、task tag からの漏洩を検査する。
- 分母には陰性・不可能・識別不能の family を原因つきで残す。生成後に陽性 family だけを選ばない。校正用と評価用の生成系列は別々に封印する。

## 3. 比較条件（arm、8条件）

主比較は全 arm へ同一の事前割付公開 trace をリプレイする（情報量の等価を保証する）。能動収集は独立した副比較とし、因果主張は「能動収集条件下での効率」に限定して別掲する。全 arm で同一の公開情報・予算・停止条件・holdout を適用し、費用は費用ベクトルとして個別記帳する（学習費と USE 費も分離）。

| arm | 許容範囲 | 切り分けるもの |
|---|---|---|
| FULL | 分節化・anti-unification・述語・第一階技能・再束縛可能な二階スキーマの構築と使用 | 主張の本体 |
| OFF | FULL の同一訓練済み snapshot で獲得物の USE のみを評価時にマスク（同一性は digest で確認） | 獲得物の実利用効果 |
| PRED-ONLY | REC に加え、獲得述語と第一階技能・マクロまで。二階スキーマの構築は禁止 | 述語発見と二階スキーマ構築の分解 |
| REC | 観測に対する学習済み feature map のみ。実行可能な述語・分岐は作らない | 再符号化だけで説明できるか（対抗仮説） |
| RANK-ONLY | 固定 H+ 候補集合に対する探索順序の学習のみ | 優先順位学習だけで説明できるか |
| FIXED-IF | 完成済み高階スキーマを seed として贈与した強い対照（贈与アドバンテージを開示する。「同一 seed」とは記さない） | 完成構造の供与との分離 |
| LOOKUP | 凍結した距離関数・容量・abstain 方針による episode 記憶の検索のみ | 記憶・再利用だけで説明できるか |
| H+ | 同一 runtime・同一候補空間・同予算の固定 grammar 探索（無制限 oracle は主成績に含めない） | 固定表現の天井（同予算） |

- 帰属の読み方を事前に固定する: FULL>OFF かつ行動差あり＝実利用寄与。FULL>REC のみ＝再符号化以外の何か（述語かスキーマかは未確定）。FULL>PRED-ONLY＝二階スキーマの増分候補。差が「非有意」であることは同等の証明ではなく、等価性は §6 の規則でのみ述べる。
- 技能昇格は AND ゲート: (i) holdout 前逐次予測の損失改善または維持、(ii) 総 MDL の改善、(iii) 独立課題族への利用証拠、(iv) 原始呼出予算の非超過。能動探索の EIG は proxy として扱い、最終判定は外部 holdout で行う。

## 4. seed 在庫と grammar 監査（MR3 の運用形）

- 評価器が提供する node は ATOM（原子行動）／SEQ（連接）／BIND（変数束縛）／COMPARE（等値・順序、型付き被演算子）のみ。学習側の構成 operator は compose／abstract（anti-unification）／predicate-slot（経験由来の述語で埋めるスロット）／branch-construct（述語・then・else の3スロットを持ち、経験由来の記号でのみ充填可能な分岐 node の構築）とする。
- 初期 snapshot には分岐 node のインスタンスも述語も存在しない。分岐の評価意味論は seed のバイアスとして明示し、獲得と呼ぶのは「経験由来の型付き述語＋再束縛可能な分岐構造の構築」に限る。この意味論の供与は全 arm で対称であり、非対称なのは完成構造の贈与の有無だけである、と開示する。
- 凍結前に grammar 監査表を添付する: 全 node type と arity、AST constructor、束縛規則、初期定数と特徴量、記号生成 operator と prior・探索順序、evaluator と learner の共有コードと read path。
- 反証試験: 学習を行わない空 snapshot で、完成済み If や意味述語を名前参照で呼べないことを確認する。

## 5. 測定と判定

- 予算軸は1つ: 有料原始操作呼出の累積 b（上限 B）。episode 数・問い合わせ・候補評価・成功フィードバック数・CPU/wall/RSS・学習準備費は費用ベクトルとして別掲し制限する。
- AULC の定義を凍結する: 各評価 family f について、checkpoint ごとの成功率 s_f(b)（棄権・打切り・INVALID は分母に残す）を等間隔 checkpoint で台形積分し (B+1) で正規化したものを AULC_f とする。評価 score は学習側へ一切戻さない。
- 主エンドポイント: holdout（G1/G2）での family ペア差 Δ_f = AULC_f(FULL) − AULC_f(control)。最強対照の事後選択には family 単位の同時信頼区間（max-T bootstrap 等）で対処し、全対照の成績・区間・NULL/NEGATIVE を表示する。
- 判定の階層を固定する: 第一に AULC（候補: 最強対照比 +0.15 かつ同時95%区間下限 >0）、追加ゲートとして予算 B 時点の達成率（G1 候補90%／G2 候補80%、対照差 +10pp 以上）。候補値は校正（§7）で一度だけ改訂でき、改訂範囲・判断者・ログを事前に固定する。データ確認後の再採点はしない。
- G2 の前提検査: 長さ13〜16の各類型について上限16の下での可解性と最短経路を校正で列挙する。容量により到達不能な事例は設計規則として事前に除外し（スキーマ失敗として計上しない）、容量境界の事例は別区分で報告する。解ける G2 family が不足する場合は Owner 判断による設計版の更新として扱い、値を黙って動かさない。

## 6. 評価 family 数の決定規則と切替（Owner 採用済みの手順）

- TRAIN family 数（候補24）は学習側の工学候補であり、評価 n とは分離する。
- 独立単位は「事前登録した法則生成文法からの独立抽出（iid draw）」とし、各 draw を1 family とする。法則の階層（族→テンプレート→draw）を台帳化し、テンプレート層で層化した結果も併記して見かけの n の膨張を監査可能にする。
- 評価 n は、校正で実測した分散（discordance／AULC 差の SD）から、凍結する効果量下限に対して検出力80%・片側 α=0.025 を満たすよう、事前に固定した計算規則で決める。目安の感度: 二値10pp 差で discordance 20〜30% なら約149〜227、AULC 差0.15 では SD 次第で約22〜56（いずれも計画用の仮定値）。
- 必要 n が生成可能な独立法則数を超える場合は、弱い対照への変更はせず、「有限法則集合の完全列挙による、その集合に限定した記述的認定」へ切り替える。切替の発動条件も本節の規則として事前に固定する。

## 7. 機会診断 K0 と校正プロトコル（いずれも非採点・正式 holdout に触れない）

K0 は校正系列の family のみで実施する。oracle 可解性は機会の上界に限定し、STOP 判定には使わない。列挙が完結しない場合は UNKNOWN とし、不存在を主張しない。

| 診断 | 実行定義 | 結論 |
|---|---|---|
| K0-a 分岐証人 | 対照ペアについて、ホライズン H 以内の共通合法 open-loop 系列を全探索し、同時成功系列の有無と、公開観測で分離する合法条件付き方策の有無を記録 | 証人が皆無なら当該課題設計を STOP/REDESIGN |
| K0-b 公開識別性 | 予算内で到達可能な公開履歴の同値類を列挙し、異なる必要行動を要求する法則が分離できるか、情報が行動選択前に到着するか点検 | 区別不能なら当該課題設計を STOP/REDESIGN |
| K0-c 同予算での余地 | 先渡しなしの固定 H+・open-loop・RANK-ONLY 等を同一公開情報・同一予算・同一ホライズンで校正評価し、達成率と AULC の改善可能幅を記帳 | 強対照が飽和し必要差を満たし得ないなら再設計/STOP。可解でも高コストなら機会ありとして継続 |

- 校正では K0 に加え、世界容量（§5 の G2 検査）、強対照の飽和度、費用分布、分散（§6 の n 決定用）、goal 識別性を測る。校正用 family・seed・receipt は評価用と分離して封印する。
- 校正による文書改訂は1回まで、改訂可能範囲を事前に限り、判断ログを残す。改訂後の文書・生成器・分割・分析コードの digest を凍結 receipt として Owner が別途承認する。
- **校正の実施自体が独立した実行行為であり、別途 Owner GO を必要とする。** 本ドラフトの採用は校正 GO を含まない。

## 8. キル条件と結果の扱い

- K0（§7）: 設計前の STOP/REDESIGN 判定。測定値を消すものではない。
- K1: 事前固定した診断 family 上で、同一 snapshot・同一公開状態・同一乱数系列の ON/OFF 強制比較を行い、選択行動・合法トレース・記号呼出を監査する。差がなければ獲得物の実使用を認定しない（全状態での無差は主張しない）。
- K2: FULL と REC の差の不在は、それだけでは証拠不足とする。再符号化で説明できることの積極的な証拠には、事前指定した等価性マージン内に信頼区間が収まることを要求する。PRED-ONLY との比較がなければ述語とスキーマの帰属は未確定とする。
- K3: 結果は「統計的に負」「実用的に小さい（幅は事前固定）」「推定不精確（INCONCLUSIVE）」を別 outcome kind として報告する。最強対照の選択バイアスは §5 の同時区間で調整する。
- K4: target・生成規則の漏洩、評価情報の学習への逆流、予算の非等価が独立監査で認められた結果は INVALID とし、原因と範囲を監査台帳に残す。同じ評価を再スコアしない。
- 点火診断 D0〜D3 は仮説族 H0 相対の診断であり、無条件の不可能性証明ではない。陰性世界（H0 で十分）・識別不能・予算不足・修復不能の各条件で誤点火と見逃しを区分する。

## 9. ログと再現性

- WORLD-R §4 の最小契約に加える: 法則 family の親 ID と非公開 manifest hash（評価側のみ）、split 境界、goal contract version、task ID 生成法の監査 hash、公開観測と private truth のアクセス制御。
- checkpoint ごとの累積経験・原始呼出・候補評価・有料問い合わせ・成功フィードバック・学習準備費・USE 費・CPU/wall/RSS・欠測と timeout。予算の等価性は単位ごとに独立照合する。
- 記号系譜: feature-only／predicate／first-order macro／second-order schema の型、生成前後の依存先、前提条件と反例、proposal・rejection・promotion・USE・OFF の digest を AST で監査可能に残す。
- 学習者は評価 family の score・hidden target・生成 seed・正解列・親法則名・評価途中の統計へアクセスできない。評価レポートは凍結 snapshot の集約後にのみ公開する。全 arm の失敗・棄権・invalid・STOP・陰性結果を保全する。
