## 0. 確定済みの前提（争点にしないこと）

1. R0-EはGOで閉じ、R1-ENG（2bit N/S/R/EのM_use工学診断）は成果物PR #171が受入合格・マージ済み（merge commit `67f5764`）。
2. R1-ENGの診断結果: パイプライン（公開境界→照会前commit→公開証拠のみの合成→独立validator→Sleep-lite→immutable Snapshot→fresh dispatch→fallbackを残すbody OFF）は仕様どおり動作した。
3. しかしRケースでは、識別の過程で2bit全4入力が公開済みとなり、body OFFでも同一Snapshot内のepisodic lookupが全点を再現した。ON/OFFの予測・合法行動の差は**ゼロ**だった。
4. したがって現状の科学ラベルは、M_use=未認定（方法文書の定義上、予測・合法行動の差が必要）、M_gap / N_rep / U / T = NOT_EVALUATED のままである。
5. これは実装の失敗ではなく、凍結方法文書が予告していた構造的な結果である（Claim Certificate MatrixのR行: 「4点lookupが合法で使えるなら `G_effective=0` もあり得る」、紙上エピソードt8）。

## 1. 問題の所在（監督者の診断）

2bit世界で因果差が消えた理由は2つに分解できる。

- **(a) 入力域が小さすぎる**: 識別に必要な照会で入力域の全点が公開されてしまう。未公開の入力が残らないため、「保存したbodyでなければ答えられない入力」が存在しない。
- **(b) fallbackが無制限に強い**: episodic lookupは公開された全点をそのまま保持・再生できる。容量・費用の制約がないため、表の暗記が常にbodyと同等になる。

一方で、世界を大きく・難しくすると、R0で学んだ2つの失敗条件が戻ってくる。

- **識別可能性の喪失**: 公開証拠が入力域の一部しか覆わないと、複数の法則が証拠と両立し、targetが一意に定まらない（Nケースの失敗）。「bodyが間違った法則を合成した」のか「そもそも識別不能だった」のかが区別できなくなる。
- **実効閉包の列挙不能**: fallback側に一般化ヒューリスティクス（近傍、多数決、パターンマッチ等）を許すほど、`H0_effective(B)` を結果を見る前に網羅的に固定することが難しくなり、弱い比較器への勝利を能力獲得と誤認する危険が戻る。

問いはこの緊張の内側にある: **「暗記では届かないが、識別は可能で、比較器は事前に固定できる」世界を最小構成で設計できるか。**

## 2. 候補方向（叩き台。採用を意味しない）

| 候補 | 仕組み | 期待される因果差 | 主な危険 |
|---|---|---|---|
| **W-A: 入力域の拡大＋照会予算** | 例: 3bit以上の入力域で、合法照会は予算内に限る。targetは合成的な法則（例: 変数対のXORの合成）。識別に必要な点だけが公開され、残りは未公開のままfresh USEに回る | bodyは未公開点でも構成的に予測できる。lookupは公開点しか答えられない | 未見汎化そのものが論点化する。一般化ヒューリスティクスを持つfallbackとの区別、識別可能性の事前証明が要る |
| **W-B: 容量制限つき記憶** | 入力域は全点公開されうるが、Snapshot側の保持容量（エントリ数・ビット数）に上限。bodyは法則を圧縮表現として保持する | 等容量ではlookupが全点を保持できず、bodyだけが全域で正答する | 圧縮・Uの主張に滑りやすい。記述言語・コード長の事前固定が必須で、M_gapではなく別主張になる可能性 |
| **W-C: 合成再利用（2段課題）** | 第1課題で獲得したbodyを、第2課題の部分関数として再利用する。第2課題の入力は第1課題の公開点と一致しない | lookupは課題をまたいで転用できないが、bodyは部品として使える | 転移Tの領域に踏み込む。ゲートの順序（Mの前にTをやるのか）の正当化が要る |
| **W-D: 費用差のみ** | 予測は一致するが、body利用の方が照会・計算・復元のコストが低い | 行動差ではなく費用差 | これは方法文書上Uの主張。因果差（M系）の設計としては不適格と監督者は考えるが、反論があれば述べよ |

## 3. 質問（QR1〜QR8）

**QR1（主ルート）**: W-A / W-B / W-C のどれを主軸にするか。複合案・別案でもよいが、主ルートを1つ選び、従属・除外する候補と理由を述べよ。自分の案への最も強い反対意見も明示すること。

**QR2（fallbackの固定）**: 主ルートの世界で、同一Snapshot内の合法fallback（episodic lookupの容量と保持方策、一般化ヒューリスティクスの有無と種類、H0候補集合、dispatch規則）を、結果を見る前にどう定義すれば、`H0_effective(B)` を列挙・固定可能に保ちつつ、不当に弱くもならないか。具体的な定義案を示すこと。

**QR3（未見入力と対照）**: fresh USEに未公開入力が含まれる場合、bodyの予測差が「構成的な合成によるもの」であることを、単なる「fallbackのカバレッジ不足」と区別して示すには、どの対照armが必須か（例: 永続化しないSTATIC-H+合成、意味同値fixed macro、policy/rank-only、容量拡大lookup等）。各armが何を棄却するためのものか対応づけること。

**QR4（識別可能性）**: 部分的な公開証拠のもとでtargetが一意に識別できる条件を、事前の紙上証明としてどう用意するか。照会予算、公開点の選び方（固定方策の範囲）、識別不能と判定する条件（Nへの帰着）を具体化すること。

**QR5（認定ラベル）**: 主ルートで成功した場合、凍結方法文書の枠内で認定できる最大ラベルは M_use か、M_gap か、その他か。行列のどの行・条件に対応するかを示すこと。枠内で認定できない場合、その不足は方法のどの条項にあり、改訂案として何が必要か（改訂は本回答では決定できない前提で、分離して提示すること）。

**QR6（STOP条件）**: どんな結果が出たら「この方向では因果差は作れない／主張できない」と判断すべきか。特に、単純なfallback（容量内lookup、単純ヒューリスティクス）が全域でbodyと一致した場合の扱いと、弱いfallbackへの差し替え禁止をどう担保するか。

**QR7（最小ステップ）**: 次に許可すべき最小の作業は何か。紙上設計のみで止める範囲と、実装を伴う場合の最小fixture（既存 `packages/r1_eng` の拡張か、新規パッケージか）、工学テストと科学採点の境界を具体化すること。あわせて、今回**やらないこと**のリストも提示すること。

**QR8（ゲートの位置づけ）**: この作業は因果アーキテクチャ案のゲート系列（R2-M等）のどこに位置づくか。ゲート名、入口条件、出口条件（何が揃えばOwnerが次を判断できるか）を提案すること。
