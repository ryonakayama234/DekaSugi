## 0. この質問票の目的

GATE-R0について、MuseとChatGPTはいずれも **REDESIGN** を推奨した。しかし、REDESIGNは「過去のNULLを研究証拠として扱わず、概念獲得を検証可能な形に作り直す」という研究方法の判断であり、**DekaSugiというAIを、具体的にどのような姿へ、どの順序で育てるのか**までは決めていない。

Owner（中山）は、この開発方針をClaudeだけで決めず、Research LeadであるChatGPTにも独立した案と批判を求めることにした。本書はそのための協議質問票である。

本書は次の行為を許可しない。

- 新規実装、実験、採点、封印済み評価の再実行
- Draft PR / Issueのclose、merge、整理作業の実施
- 本書または回答だけで「合意成立」「実装GO」と宣言すること

回答後、Museが独立に精査し、最終決定はOwnerが行う。

## 1. 前提として共有する事実・制約

1. DekaSugiの目的は、小さな中枢が外部の知識・技能・道具を再利用し、新しい操作体系を獲得できるかを検証することである。
2. 主要な軸は、Active Learning、道具化・外部化知能、それに伴うWake-Sleepである。
3. 巨大な事前学習LLMは初期実験では使わない。
4. 学習は、少なくとも「記号合成」「非パラメトリック統計」「学習されたパラメータ表現」を区別する。
5. 過去のNULLの多くは、世界側に学習・適応で得られる機会があったか未判定であり、学習器の失敗を直接証明しない。
6. 同時に動かす科学的決定は1つだけに絞る。研究本体の周囲に、測定・統治・証拠保全の作業が膨らんだことも停滞の一因である。
7. 「新しい概念を使えること」と「その概念を公開経験から獲得したこと」は別々に証明する。
8. Ownerは、知能を静的な蓄積物ではなく動的なプロセスとして捉えている。対話の互恵性は長期的な問いであり、現在の有限タスクに相手側の学習が存在しない以上、現段階の成功条件へ混ぜないことが論点になっている。

## 2. Museが用意した開発ルート候補

以下は決定案ではなく、ChatGPTに比較・批判してもらうための叩き台である。

### 案A: 証明先行型

最初に方法文書で、H0の実効閉包、N / S / R＋探索不足対照、強対照、生涯総費用を固定する。その後で、最小の学習閉ループの仕様を決める。

- **長所**: 過去のNULLの混線を最も確実に避けられる。実装後に成功条件を動かさなくて済む。
- **短所**: 研究装置と方法論ばかりが育ち、「AI本体」が長期間見えない危険がある。
- **最初の成果物**: 方法文書と紙上の証明・反例表。コードではない。

### 案B: 縦切り一体型

最初に、DekaSugiらしい振る舞いを1本の細い縦切りとして定義する。

> Wakeで課題に取り組み、現在の体系では説明できない公開反例に出会い、必要な観測・質問を選び、新しい型付き操作を構成し、検証して外部の道具庫へ保存する。Sleepで重複・依存関係を整理し、次のfresh課題でその操作を再利用する。

対象は1つの世界、1つの関係family、1つの操作型に限定する。方法定義は、この縦切りを評価するために必要な範囲だけ先に固定する。

- **長所**: Active Learning、道具化、Wake-Sleep、概念獲得が、最初から1つのAIの振る舞いとして見える。
- **短所**: 要素を同時に入れるため、各要素の効果を分離する対照を怠ると、過去の混線を繰り返す。
- **最初の成果物**: 1つの完全なエピソードの紙上トレースと、主張／証拠／中止条件の対応表。まだコードではない。

### 案C: 段階育成型

機会が保証された世界を段階的に用意し、能力を1段ずつ増やす。

1. S世界: 既存概念で十分なことを確認する。
2. N世界: 情報が届かず、学べないことを正しく判定する。
3. R世界: 1種類だけ表現修復を学ぶ。
4. 問い合わせ世界: 適応的な質問で初めて利得が生まれる。
5. 転移・合成世界: 保存した操作を新しい組合せで使う。

学習層も、記号的閉ループ → 非パラメトリックな記憶・検索 → 必要性が証明された箇所だけパラメータ学習、の順に広げる。

- **長所**: AIの成長過程が見え、失敗した段を特定しやすい。Ownerのプロセス観とも合う。
- **短所**: カリキュラム設計自体が大きな研究対象になり、段階を増やすほど遅くなる危険がある。
- **最初の成果物**: 各段の入口条件・出口条件を示した育成マップ。

### Museの暫定見解（同意を求めるものではない）

Museは現時点では、**Bを開発の背骨にし、Aを証拠のガードレール、Cを世界の提示順序として従属させる案**が候補になると考えている。ただし、この合成自体が「全部入り」に戻る危険がある。ChatGPTには、賛成する場合でも、主従関係と捨てる要素を明確にするよう求める。より単純な案や、STOPが適切になる条件があれば提示してほしい。

## 3. ChatGPTへの質問

各質問には「結論 / 根拠（既存文書・実験への引用、または新規提案であることの明示） / 見直し条件」を付けて回答すること。

### DV1 — 主ルートの選択

案A・B・C、Museの合成案、または別の案Dのうち、どれを主ルートにすべきか。順位ではなく、**主ルート1つと、従属させる要素・完全に外す要素**を明示すること。「全部重要」という回答は不可とする。

### DV2 — 最小の「DekaSugiらしいAI」

次段階で目指す最小システムを、1つの完全なエピソードとして記述すること。

- 初期状態と失敗
- 公開反例または観測
- 質問・観測の選択
- 新しい操作の候補生成と検証
- 保存とSleepでの整理
- fresh課題での再利用
- どこで効果を測り、どの対照と比較するか

あわせて、手作業・スタブ・人間が与えた部品で済ませる箇所と、それらを学習の証拠に数えない条件を明示すること。

### DV3 — 能力の実装順序

次の能力について、次段階の「必須 / 後回し / 当面禁止」を分類し、理由を示すこと。

- 不一致・表現不足の検出
- 観測・質問の選択
- 型付き操作の候補生成
- 候補の検証
- 外部道具庫への保存
- Sleepでの統合・圧縮・忘却
- 保存した操作の検索と再利用
- 未見課題への転移・合成
- パラメータ学習

### DV4 — 3つの軸を混ぜない方法

Active Learning、道具化・外部化知能、Wake-Sleepについて、それぞれ次を1行ずつ定義すること。

- 主張する効果
- 観測できる証拠
- 効果を分離する対照・ablation
- NULLまたは有害と判断して止める条件

特に、WakeとSleepが単なる「実行フェーズ」「整理フェーズ」の言い換えに終わらないためには、何が観測されればよいか。

### DV5 — 記号・非パラメトリック・パラメータ学習の役割

3層それぞれが、最小システムで何を担当するか。パラメータ学習を最初から入れるべき箇所があるなら、その必要性と導入トリガーを示すこと。逆に、ニューラルネットや巨大LLMを入れても解決しない問題も明示すること。

### DV6 — 最初の世界とカリキュラム

最初に扱う世界・関係family・操作型の候補を、具体的に1つ推奨すること。少なくとも次を分けて示すこと。

- 表現機会 `G_expr > 0`
- 公開情報から識別可能であること
- 適応的質問の利得 `G_inq` があるか、今回は主張しないか
- N / S / R と探索不足対照をどう置くか
- 有限で全列挙または監査が可能な範囲に収まるか

### DV7 — 実装開始までのロードマップ

方法定義、紙上トレース、プロトタイプ仕様、実装、評価を段階に分け、各段階について次を示すこと。

- 目的と成果物
- 入口条件と出口条件
- Ownerの決定が必要な点
- STOP / REDESIGNへ戻る条件
- 同時に進めてはいけない作業

特に、**どの段階の後に、どの範囲のコードなら書いてよいか**を曖昧にしないこと。

### DV8 — 既存資産と滞留物の扱い

既存のmain、Draft PR、Issue群のうち、主ルートへ再利用できる資産と、混線を避けるため凍結すべき系統を、分類基準で示すこと。今回の回答では実際のclose / mergeは行わない。過去資産を活かすことと、過去の設計に引きずられないことの境界も示すこと。

### DV9 — プロセスとしての知能と対話

学習過程を静的な最終スコアだけで評価しないために、prequentialな予測記録、予測の事前コミット、改訂履歴、snapshot digest等を、最小システムへどう組み込むか。

また、対話の互恵性は現在の成功条件に入れず長期VISIONに残すべきか。残す場合、現段階で正直に主張できるのは「対話を通じた学習過程の記録」までなのか、それ以上なのかを区別すること。

### DV10 — 最も強い反対意見

Museの候補案と暫定見解に対する最も強い反論を示すこと。特に次を検討すること。

- 合成案が再び「全部入り」になる具体的条件
- 縦切りが成功しても概念獲得の証拠にならないケース
- 方法論の固定が終わらないまま開発が止まるケース
- REDESIGNではなくSTOPを選ぶべき条件
- A・B・Cのどれでも不十分なら、代わりの案D

## 4. 回答形式

回答文書では、少なくとも次を含めること。

1. 推奨する主ルートと、従属・除外する要素
2. A・B・C・案D（あれば）の比較表
3. 最小システムの完全なエピソード例1件
4. Active Learning／道具化／Wake-Sleepの「主張・証拠・対照・中止条件」表
5. 最初の世界と能力順序
6. 実装GOまでに必要な段階と、各段階の成果物
7. Muse案への明示的な不同意点
8. Ownerが決めるべき事項の一覧

既存のrepo証拠に基づく主張には出典を示し、新しい設計提案は提案として区別すること。回答の提出だけでは合意は成立しない。

## 5. Ownerが最終的に決める事項

ChatGPTの回答とMuseの精査を受けた後、Ownerは少なくとも次を決定する。

- 主ルートはどれか
- 最小システムに含める能力はどこまでか
- 最初の世界と、主張する効果は何か
- 紙上作業をどこまで終えたら実装を許可するか
- 対話の互恵性を長期VISIONへ残すか
- 既存資産のうち何を凍結し、何を主ルートへ取り込むか
