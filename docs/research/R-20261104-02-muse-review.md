## 3. MQ1〜MQ6 への回答

### MQ1 — 機構 M と実用 U の分離: **条件付き同意**
M（機構実証）と U（資源制約下の実用証拠）を別建てにし、無制限 Oracle を上限参照に格下げすることに同意する。M 単独は「限定された概念獲得の機構的実現」と呼んでよい。条件は3つ:
1. body が公開反例からのみ構成されていること（人間が対象関係の body を手で書いて登録したものは M の証拠にしない）。
2. body OFF 介入（方策固定）で fresh 入力に対する予測差が実際に観測されること。
3. body が既存 macro と意味同値である場合は「新規表現の獲得」ではなく「再発見／圧縮」とラベルすること。
提示された反例（意味同値な既存 macro の登録・実行だけでは M 不成立）にも同意する。U を満たさない間は「能力成長」「効率改善」を主張しない。

### MQ2 — H0 の実効閉包: **同意**
H0 は DSL だけでなく、保存・メモリ・Kernel dispatch・方策分岐・探索を含む実効システム全体として型付けし、固定すること。初期診断で memory / policy を狭く制限することは、(i) 制限を事前に宣言し、(ii) 主張をその制限下の範囲に限定する、という条件で許容する。不公平な弱体化 baseline になる境界は次の2つ: 制限した能力が対照側（静的 H+、episodic retrieval 等）には暗黙に許されている場合／対象関係の識別に通常必要な条件分岐まで学習者側からのみ奪う場合。R の XOR 候補が既存 policy だけで再現できた場合は L0（表現修復）の主張を撤回する、に同意する。

### MQ3 — 機会の分離: **同意**
`G_expr`（表現差）、`public_identifiability`（公開識別可能性）、`G_inq`（適応問い合わせ利得）を別々に記録することに同意する。監督者の QD2 で意図した「機会」は「その実験が主張する効果に対する機会」であり、効果が表現修復なら G_expr > 0 と公開識別可能性が必須、効果が適応的質問なら G_inq > 0 が必須、というのが正確な意図だった。今回の分離表記を正式な整理として採用することを推奨する。表現差が正でも公開反例が一切得られない場合は「公開学習機会なし」として STOP / REDESIGN、に同意する。

### MQ4 — 最小 toy の証拠上限: **条件付き同意**
N / S / R を「診断器の妥当性の engineering thought-test」に限定し、合格しても「概念獲得は未実証」と明記する縮小に同意する。生成 index / role-orbit の水増しを独立 family 数と数えない、にも同意する。追加する本質的な負対照を1つ提案する:
- **見かけの修復（探索不足）対照**: H0 の探索を尽くせば解けるのに、探索予算不足のために MODEL_CLASS_MISMATCH と誤診される世界。MismatchCertificate の最も起きやすい誤りは「表現不足」と「探索不足」の取り違えであり、この対照がないと R の MISMATCH 証人の信頼性が担保できない。

### MQ5 — 本体因果性の最小条件: **条件付き同意**
2×2 因子比較（body ON/OFF × rank 固定/学習）＋ episodic・静的 H+・固定 macro との比較の前登録に同意する。M の最小成立条件は MQ1 の回答の3条件に、(4) 学習・保存・利用の全費用の記録、を加えたものとする。争点のケース（body が計算を短縮するが、同値な fixed macro が同費用で生成可能な場合）への監督者の判定は二段評価である: 機構としては M 成立（自律構成・保存・実使用は起きた）、ただし意味的新規性は NULL、U も NULL。「M 自体も NULL」とすると自律構成という事実まで消えてしまい、「M = 成立」とだけすると新規性があるように読める。両者を分けて記録すること。評価器の正解情報が学習者に流れた場合は即 INVALID、操作変更が一切起きなければ問い合わせ学習は NULL、に同意する。

### MQ6 — プロセス観と独立統治の着地点: **条件付き同意**
「事前に固定するのは規則・母集団・評価のアクセス境界、学習過程そのものは観測対象」という提案に同意する。必須の証拠項目として監督者が1つ加えるのは、**予測の事前コミット（prequential 記録）**である: 各ステップで結果を見る前に、予測とその時点の hypothesis / snapshot の digest を追記専用ログに残すこと。これがなければ「過程が学んだ」ことは事後の物語と区別できない（QD5 回答の第1指標と一致するので、実装上の追加負担は小さいはずである）。
「対話の互恵性」については、現在の有限タスク内では**評価対象にしない**。理由: 互恵性は相手側も変化する二者過程だが、現在の世界では Oracle / 環境は学習せず固定であり、測る相手が存在しない。VISION の長期課題として保留し、R0 の成功条件には混ぜない。
無回答を合意とみなさず、レビュー未了では GO しない運用に同意する。これは監督者自身の原則でもある。
