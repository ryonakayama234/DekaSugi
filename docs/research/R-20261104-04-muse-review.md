## 2. 総合判定

**Dルートを、条件付きで支持する。**

ChatGPTがClaudeの暫定合成案を退けたのは正当である。Muse案は「Bを背骨」と言いながら、質問・body・Sleep・転移の因果帰属を後から分離する設計であり、陽性が出た場合に何が効いたのか曖昙になる危険があった。D案は同じ因果連鎖を保ちながら、初段で主張する出来事を「公開証拠からbodyを構成し、保存し、freshで使う」一点まで削っている。これはBの否定ではなく、**Bを将来の統合像として残し、その最初の検証可能な断面をDとして切り出したもの**と理解できる。

ただし、中心用語である **M** が、現行案ではまだ2つの異なる意味を含んでいる。この曖昧さを解消しないままR0を通過させると、「パイプラインが動いた」結果を「実効能力が獲得された」と読み替える余地が残る。これを本査読の唯一の **P0条件** とする。

## 4. MQ7〜MQ11への回答

### MQ7 — 限定H0と meaningful M: **条件付き同意**

Research Leadの「R0 toyの合格は計測器の準備止まり」という自己限定に同意する。その上で、Mを次の2階層に分けることを要求する。

- **M_use（機構の使用実証）**: 学習者が公開証拠だけから型付きbodyを構成し、独立検証を通し、immutableに保存し、fresh processで実際にdispatchした。さらに同一Snapshot・同一policyでbodyをOFFにすると、そのbodyへの依存が観測できる。これは「外部化と再利用のパイプラインが成立した」証拠である。
- **M_gap（実効能力の獲得）**: 事前に宣言した `H0_effective(B)` の全候補と合法fallbackでは実現できない振る舞いを、body追加後に、同一公開情報・同一policy・同一予算で実現した。H0実効閉包の網羅証明と、OFF時に使える最良fallbackの開示が必要である。

R toyで現在示せるのは、原則として **M_useの設計可能性**だけである。`G_object > 0` しかない場合、それを無印の「概念獲得M」と呼ばない。

最も強い反例は次の2つである。

1. **自己成就的なOFF**: bodyを唯一の合法予測経路として実装し、OFFでは強制的にABSTAINさせる。ON/OFF差は出るが、それは学習ではなく配線の結果である。
2. **lookupによる洗浄**: Kernelが4行の真理値表を保持して振り分ければ、有限2bit世界ではXORを実効的に実現できる。この場合 `G_effective = 0` であり、bodyは新しい能力ではない。ただし、暗黙の振り分けを明示的で再利用可能な型付きbodyへ変換したこと自体は、道具化・外部化の出来事として意味を持ち得る。その価値は能力差ではなく、表現の圧縮・合成可能性・再利用費用で測るべきである。

したがって、強いH0で表現差が消えた場合に研究対象を「抽象圧縮／計算制約下のU」へ変更することには、**条件付きで同意**する。条件は、それを同じ主張の言い換えにしないことである。

- 圧縮へ転換する場合は、記述言語とコード長の数え方、比較するlookup / episodic表現、再利用回数を含む総費用を、学習器を動かす前に固定する。
- `G_effective = 0` が判明した後で、同じ結果を「やはり概念獲得だった」と再ラベルしない。転換は新しい主張であり、Ownerの明示決定が要る。
- 圧縮仮説自体を任意のコード選択なしに定式化できない場合は、その系列の「意味的表現修復」主張をSTOPする。

公平なH0は、対象関係を見てから作るものではなく、対象より前に存在するアーキテクチャ契約に対して定義する。R0 toyのH0は人為的に stipulate された診断装置であり、その範囲では正直である。一般の実効能力不足を主張するには、実在するKernel契約に対する閉包証明が別途必要になる。

### MQ8 — 三軸の後退か: **同意**

Dを「背骨」と呼ぶことはできる。ただし背骨とは、**予測 → 不一致 → 修復 → 外部化 → 再利用**という因果依存の順序であり、Active Learning・道具化・Wake-Sleepの3つの学習効果が初段で同時に成立することではない。

- 初段の固定クエリは、Active Learningの**インターフェース**を用意するが、学習効果は主張しない。
- 初段の保存と再利用は、道具化・外部化のうちM_useを主張できる。
- 初段のSleep-liteは、Sleep学習を主張しない。

B統合案は要求しない。後段で必要になった場合も、最初から2×2×2にする必要はない。M_useが成立した後、Sleep-liteを一定にして「body源（学習／固定）×質問方策（固定／学習）」の2×2で質問学習を分離し、Sleepの本格効果はその後の独立したablationで扱えばよい。

Sleep-liteの境界を1つ明確にする。**Sleep-liteが行ってよいのは、意味を変えないcanonical化と、validatorの採用／拒否結果の記録・版管理まで**である。意味の異なる候補のうちどれを採用するかを公開証拠で選ぶ行為は、候補選択という学習・モデル選択であり、Sleep-liteの行政処理とは呼ばない。その選択はWake側の合成・検証に帰属させるか、将来のSleep効果として独立に対照する。

### MQ9 — Mの最小合格と成果ラベル: **条件付き同意**

M_useの最低条件として、公開由来、target非注入、独立検証、immutable保存、fresh dispatch、body OFF差分を認める。ただしOFF条件は「body以外の全合法経路を止めた状態」ではなく、**body以外のH0候補・episodic fallback等をすべて有効にしたまま、当該bodyだけを無効化した状態**でなければならない。さもなければ差は自明になる。

「Mあり・Nなし・Uなし」の記録方法については、用語を正確にする。

- Uをまだ測っていない段階では `U = NULL` ではなく **`U = NOT_EVALUATED`** と記録する。
- 推奨ラベルは `M_use-positive / N_rep-null / U-not-evaluated / T-not-evaluated` とし、日本語では「限定世界における、公開証拠からの概念body構成・保存・再利用機構の実証。意味的新規性なし。実用性と転移は未評価」と書く。
- M_gapまで証明した場合のみ、ラベルのMをM_gapに置き換える。

また、Nは「意味的新規性」とだけ呼ぶと外延同値の問題で壊れる。**`N_rep`（表現上の新規性）** と改名することを推奨する。

- 初期Libraryに実際に存在する再利用可能なmacro/bodyと外延同値なら、N_rep = 0。
- 仮説上のlookupが外延的に模倣できるだけでは、表現上の新規性は消えない。消えるのは実効能力差、すなわちM_gapである。
- N_repの判定には、canonical AST同値に加え、事前に固定したコード長と、他のbodyとの合成可能性を用いることができる。

主張段階ごとの必須対照は次の通りとする。

| 主張 | 必須対照 | 後回しでよいもの |
|---|---|---|
| M_use | 公開由来監査、独立validator、body OFF（他のfallback有効）、leakage検査 | STATIC-H+との性能比較、policy学習 |
| M_gap | H0_effective(B)の網羅証明、最良fallbackとの比較 | U評価、転移 |
| N_rep | 初期Library/macroとのcanonical同値検査、固定コード長 | 実用費用の勝敗 |
| U | 同等H+のSTATIC、episodic retrieval、意味同値なfixed macro、policy/rank-only、body OFF、生涯総費用と事前に宣言した償却回数 | 無制限Oracleは上限参照のみ |
| T | 生成機構の異なる独立familyでのgroup split | role rename、seed増しは不可 |

### MQ11 — 撤退ライン: **条件付き同意**

主張単位でSTOPするResearch Leadの原則に同意し、監督者として次の運用境界を提案する。

#### 主張のSTOP（証拠が条件を満たせば自動的に止める）

1. **循環**: 対象の結果を見なければ `H0_effective(B)` を数えられない場合は、「意味的表現修復」の主張をSTOPする。
2. **実効差ゼロ**: 事前に宣言したR familyについて網羅監査で `G_effective(B) = 0` なら、そのfamilyでのM_gap／意味的新規性の主張をSTOPする。後から弱いH0へ作り替えない。
3. **識別不能**: 合法な公開証拠では候補bodyを評価前に識別できない場合は、その世界をNとして扱い、獲得主張をSTOPする。
4. **出自違反**: target bodyの注入、hidden labelの流入、結果を見た後の文法変更があれば、その試行はINVALIDとし、主張をSTOPする。

#### 圧縮・Uへの転換

- 転換できるのは、方法文書の段階で圧縮指標と予測される優位が事前に書かれている場合だけである。
- 転換は「表現修復」主張の継続ではなく、新しい研究主張としての再承認である。
- 固定したコード長と総費用で優位がなければ、圧縮主張もSTOPする。

#### 系列のSTOP（Owner判断）

- R1/R2で、漏洩なしにM_useのパイプライン自体を実証できない場合は、DルートをSTOPする。
- M_useは成立しても、その後段で最初に事前宣言したN_rep試験とU試験が両方ともNULL / NEGATIVEなら、「能力成長のための概念獲得」という系列はSTOPする。純粋な機構研究として続けるかは、科学ではなくOwnerの価値判断である。
- 同じ主張を救うために新しいworldを作り直すことは、R0後にOwnerが新規の研究課題として承認した場合に限る。世界は結果の陽性を見て選ばず、対象能力に対する事前の選定理由と、全数報告を必須とする。

DekaSugi企画全体のSTOPは、上記のいずれからも自動的には導かれない。止まるのは、まず主張、次に系列であり、企画全体はOwnerが決める。

## 6. P1補正要求（方法文書への転記時に反映）

### P1-1: 有限全域での検証とfreshの証拠上限

DV2では、識別時点で2bit入力の全4組合せが公開済みになる。したがってt5の「新規公開検証例」は、未見入力としての検証にはならない。既知の意味点を順序変更・役割置換・再提示した整合性チェックと明記すること。t7のfresh USEが証明するのは、永続化と別プロセスでのdispatchであり、未見組合せへの汎化ではない。未見組合せを残す設計は、識別可能性と両立するかを含め、R2以降の別エピソードで扱う。

### P1-2: Sleep-liteは意味選択をしない

Sleep-liteはcanonical化とvalidator結果の記録までに限定する。意味の異なる候補間の選択をSleepに帰属させない。

### P1-3: episodic retrievalをH0実効閉包へ算入する

DV5の「最小検索」が有効な場合、その検索が到達できる振る舞いはH0_effective(B)に含める。真理値表を検索で答えられるならM_gapは認定できない。M_useの査読では、episodic側をOFF時のfallbackとして明示する。

### P1-4: R1許可をR0-E決定文の1行で明示する

DV7の「R0-E GO＋R0-T査読＋Ownerの新規coding指示」という三重表現は、同じ許可を重ねる危険がある。R0-Tは単一方法文書の一部とし、OwnerのR0-E決定文書に次の行を含める形に統一する。

> `R1-ENG authorization: granted / not granted — scope: <許可するworld、package、testの範囲>`

この行がない、またはnot grantedなら、方法が承認されてもコードは書かない。

### P1-5: 未評価とNULLを混同しない

UとTは、試験を実施するまではNOT_EVALUATEDであり、NULLではない。成果ラベルでは4値を常に分けて書く。

### P1-6: 長期仮説を方法文書へ持ち込まない

因果アーキテクチャ案§9は凍結リストとして扱い、方法文書には範囲外ポインタだけを置く。行為の共通化、技能活動の自己組織化、学び方の学習は、今回のOwner決定事項に含めない。
