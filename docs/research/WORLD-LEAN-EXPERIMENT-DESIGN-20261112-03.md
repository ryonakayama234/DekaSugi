## 1. 世界と原子操作をここまで決める

状態は `(buffer, cursor, selection, clipboard)`。bufferの記号は4個の不透明なSym、上限16。cursorは挿入境界0..長さ、selectionはnoneまたはanchor/head、範囲は半開区間。全状態を公開する。goal／法則／生成seedは公開しない。観測欄名・位置アクセス・型は人間が供給する基盤であり、その発見は主張しない。

**原子操作は現行11種をすべて残し、追加0・削除0を推奨する。** UIキーに相当する小粒度を保ち、コピーをINSERT列に置き換えた世界に縮退させないためである。11は操作の種類数であり、INSERTの4引数を数えた具体tokenは14個になる。

| 操作 | 本案での効果・端の扱い | 残す理由 |
|---|---|---|
| MOVE_LEFT | cursorを1左へ。端でno-op。selectionをnoneにする | 相対位置への移動・左側編集 |
| MOVE_RIGHT | cursorを1右へ。端でno-op。selectionをnoneにする | コピー後の挿入位置移動 |
| INSERT(s) | selectionがあれば範囲をsで置換、なければcursorに挿入。cursorを挿入末尾へ、selectionを解除 | 新記号の入力、選択置換 |
| DELETE_BACK | 非空selectionを削除。なければ左1記号を削除。cursorを削除位置へ、selectionを解除 | 前後の違いを持つ編集 |
| DELETE_RIGHT | 非空selectionを削除。なければ右1記号を削除。cursorを削除位置へ、selectionを解除 | 同上。BACKだけで代用して探索を歪めない |
| SET_ANCHOR | anchor=head=cursorの空selectionを作る | 範囲操作の始点 |
| EXTEND_LEFT | selectionがある場合headとcursorを1左へ。端／selectionなしはno-op | 左向き範囲・役割交換 |
| EXTEND_RIGHT | selectionがある場合headとcursorを1右へ。端／selectionなしはno-op | 複数記号の複写 |
| COPY | 非空selectionをclipboardへコピー。状態の他欄は維持 | 記号列を再利用する技能 |
| PASTE | clipboard非空なら選択範囲を置換、またはcursorに挿入。cursorは挿入末尾、selection解除 | COPYと連結して初めて成立する操作 |
| CLEAR_SELECTION | selectionだけnoneにする。cursor維持 | コピーした範囲の再置換を避ける |

INSERT／PASTEで上限16を超える場合、全状態を変更せずno-op。DELETEで削除対象なしもno-op。正規のno-opも1原始呼出として課金する。型違い・不正Sym・不正ASTはFAULTとしてその試行を失敗にし、成功の分母に残す。任意Python／shellの実行は不可。

旧SPEC付表Aで曖昧だった通常MOVEとselectionの関係、DELETEの選択時の挙動を本案では上表に一意化した。旧意味論を修正したことにはせず、新世界版 `lean-editor/1` の提案とする。WORD-Rの操作粒度は保つ。

SEARCH／REPLACE／SELECT_WORD／GOTO_END／IFという世界操作を追加しない。条件評価は学習器が作ったグラフの内部処理で、編集の一手と混ぜない。`finish`は提出を通知するプロトコル信号であり12番目の編集操作ではない。

**終了はfinishまたは12原始呼出で一度だけ採点**。途中の成功自動終了や成否通知はない。12手に達した状態を自動提出し、未提出を隠さない。これで「Aを一度作ってからBも作り、成功時の早期終了に任せる」抜け道を避ける。12は最長の生成body6手に同じ6手の回復余地を残すためで、全方策の到達性証明ではない。

## 2. 課題生成：小さくても条件と技能を組み合わせる

### 2.1 評価側だけが持つレシピ

初期buffer長はTRAIN／主holdoutで4..6、cursorは1..長さ−2、selectionなし・clipboard空。各長さとcursorを均等に選び、記号列は4記号上の一様列とする。cursorの左右と2記号範囲を合法に読み／編集でき、容量16にも収まる最小の範囲である。追加診断だけ長さ7..8を使う。

生成法則は `if p(initial_state) then body_i else body_j`、i≠j。条件は**初期状態で1回**評価する。body中のSym読み出しは実行時の現在状態から行う。評価側のレシピに意味名があっても、学習器にレシピ・条件ID・bodyID・表の列番号を渡さない。

| 生成側の条件候補 | 初期状態で読む関係 | 選ぶ理由 |
|---|---|---|
| p0 | cursor位置のSym＝直前のSym | 局所の一致 |
| p1 | cursor位置のSym＝先頭のSym | 局所と端の関係 |
| p2 | 直前のSym＝末尾のSym | 別の位置役割 |
| p3 | 先頭のSym＝末尾のSym | cursor以外の関係 |

| 生成側のbody候補 | 原子展開 | 最大手数・理由 |
|---|---|---|
| d0 | INSERT(現在cursorのSym) | 1、値の再束縛を必要とする複製 |
| d1 | DELETE_RIGHT | 1、削除と挿入の違い |
| d2 | DELETE_BACK | 1、左右の役割差 |
| d3 | SET_ANCHOR; EXTEND_RIGHT×2; COPY; CLEAR_SELECTION; PASTE | 6、2記号を選択して直後に複写する連結 |

成功条件は生成レシピを初期状態から実行した**最終4欄すべてとの一致**。bufferのみだと隣接同字の左右削除が同じ答えになりやすいため、cursorとclipboardも含める。公開デモも4欄の入出力を示す。これは「普通の編集課題」全体ではなく、操作結果を厳密に指定した小さな状態変換課題である。

条件は4、順序つきの異なるbody対は12で、48法則レシピ。これは評価側の有限課題メニューであり、FULLの初期技能在庫でも探索用の正解カタログでもない。d0〜d3を学習側へ関数として供給しない。条件の等号や位置読み出し自体は共通のメタ基盤で、**どの読み出しを比較し、どこへ分岐し、何を再利用するか**が学習側の仕事となる。

### 2.2 TRAINと未見組合せ

bodyの無順序対を先に分割する。TRAINは{d0,d1}・{d1,d2}・{d2,d3}、HOLDOUTは{d0,d2}・{d0,d3}・{d1,d3}。各対の両向きと4条件を含め、TRAIN24法則／HOLDOUT24法則とする。ある法則のthen/else逆転を別splitへ漏らさない。各bodyと各条件はTRAINに現れるが、holdoutのbody対は現れない。

この分割は**既知要素の未見対への局所的な再組合せ**を測る。新述語族・新しい基本編集・新世界への転移ではなく、直積の一部を隠しただけで強い構造一般化を証明したとは言わない。レシピの意味的同値についても全空間の独立性を証明しない。

各実現seed内で24法則を等重みにする。主評価は各法則2 query（p真／偽を1件ずつ）、計48 query。2は分岐両側を一度ずつ外さず、計算を抑える最小数。buffer・cursorの重複は同一法則内でデモとqueryの間に認めない。分岐条件付きの分布なので、これは自然な一様buffer分布の成功率ではなく**真偽を均衡させた設計分布**の成功率である。

各seedで別途、長さ7..8・新Sym表示名のqueryを各法則2件、計48件用意する。これは**最終checkpointのみの副次診断**で、主評価の有意性／合格を救済しない。表示改名と長さを同時に変えるため、両要因を個別に切り分けたG1/G2認定はしない。

### 2.3 goalをどう知るか／識別不能をどう扱うか

全腕に、lawごとに同じ**6組の初期状態→最終状態デモ**を一括提示する。行動列・p／body名・今回のqueryの答えは提示しない。デモのp真／偽を3件ずつにするが、どちらが真かというラベルは隠す。これはSPEC-06 §1の仕様デモという発想の縮小転用であり、教師の操作手順の模倣ではない。ただし入出力教師情報は与えているので、無教師学習とは呼ばない。

デモは上記初期分布から条件付きで引く。最小の配列順・乱数順を固定し、都合のよい例が出るまで識別性を見て引き直さない。真偽条件と同一法則内の重複回避のrejectionのみ許し、各itemの候補初期状態drawは4096回で打ち切る。超過はGENERATION_STOPとして全runを保留し、law除外や別seed補充をしない。4096は通常の条件確率約1/4に比べ十分大きく、生成ループを有限にする工学上限であり識別性の保証ではない。6は両分岐各3例で、1例だけの偶然を少し減らすための候補であり、法則の一意同定を保証しない。

評価側は48レシピだけについてデモ一致集合を求め、queryで予測が割れるかを記録する。この小さな監査でさえ曖昧なら、**除外・再抽選せず全腕でそのqueryをそのまま採点**し、AMBIGUOUSの件数と、公開デモだけではレシピを一意にできない旨を報告する。有限レシピ内の一致監査は任意方策に対する完全なK0-bではない。

全体の10%超の主queryがレシピ内で曖昧なら（仕様不足が効果0.10と同程度になる水準）、経験効率の認定候補にしない。結果を設計不足として保存し、新版のデモ提示を考える。同じholdoutで6をさらに増やすなどの救済はしない。曖昧性が小さいことも未確認であり、設計審査で重点確認を求める。

デモは全checkpointで固定。queryごとの作業メモリで推論してよいが、query間・checkpoint間で評価由来の状態を持ち越さない。したがって**6仕様例つき・追加問い合わせ0の転移**であり、zero-shotではない。入力仕様を読む費用もCPU・例数・原始シミュレーション費に記録する。

## 3. 学習・推論の具体案とseed在庫

### 3.1 与える基盤／与えない完成物

FULLの初期在庫は、11原子操作の信頼された実行意味論、4欄の型付き読み出し、長さ・位置参照、等号／順序比較、変数束縛、連接、任意の有限decision graphを解釈する機構だけ。位置参照はcursor±1、先頭、末尾を含むと事前開示する。これらの手製の帰納バイアスと原子遷移の既知性を隠さない。

初期snapshotの述語AST・マクロAST・BRANCHインスタンス・再束縛スキーマは**すべて空**。p0〜p3、d0〜d3、完成したSELECT_BRANCHは置かない。Graphを組み立てるconstructorはあるが、使う条件・枝・共有部分・引数化はTRAIN履歴から構成する。人間の4条件×4bodyカタログをFULLに配布しない。根本的な表現力の新設とは主張しない。

AST上限は展開前32 node・深さ6、保存候補64件、1提案の原子展開上限12。浅い1分岐と6手bodyを収め、再帰・無限ループを排除するための候補。macro呼出を展開したnode数と実行原子数も別途数え、呼出1回に隠さない。これは有限計算資源であって、完全探索の宣言ではない。

### 3.2 同一経験をどう与えるか

学習経験軸bは、全腕に同じ順で配る**実環境の原子操作イベント数**。b=0,512,1024,2048,4096でsnapshotを保存する。2倍間隔は初期の速さと終盤の停滞を5点で拾い、連続曲線を全点評価する費用を避けるため。総上限4096は16 seedでも実環境イベント65,536件に抑えるためで、旧CALのB_finalとは別物である。

TRAIN24法則を巡回し、24件単位の順序をseed付きで置換する。8手の合法なランダム操作ブロックを512本配る。各ブロックは新しいTRAIN初期状態から開始し、初期／操作／全観測／提出時の成否を記録する。reset・状態保存はブロック開始時だけ。選べる14 tokenから一様に選び、no-opも残す。8手は6手のcopy bodyを経験し得る長さだが、正解列を含める保証はしない。成否はブロック末尾だけ返す。各lawは意味を符号化しない独立な公開tagで同定し、初遭遇時にそのlawの6仕様デモを配る。b=0ではTRAINデモも未提示、最初の24ブロック後には144デモ対が提示済みとなる。この追加仕様情報量もcheckpointごとに別掲する。デモ・操作・失敗を含む公開trace digestは全腕で同一。

最初の実験で能動収集を混ぜない。ランダム経験が疎すぎる可能性は、陽性を約束しない本案のリスクである。実装後の人工fixture検証と公開TRAINの費用診断は、別許可で行い、正式holdoutを見て台本を足さない。

bとは別に、既知原子意味論で**公開TRAIN／公開デモだけ**を再生する内部シミュレーション費を数える。内部シミュレーションも真のCPU／原始呼出費を持つ。学習済みモデルの予測を実世界観測として追加計上しない。主張は実環境経験の節約であり、総primitive／総CPUの節約ではない。

### 3.3 実装できる範囲の学習器候補

64実環境イベントごと（最大64回）に更新する。観測された短い操作区間を連接候補とし、同じ変化を持つ区間から一般化単一化でSym／位置を束縛変数にする。予測と結果が食い違うTRAIN例の対から、共有された読み出し項の比較を候補化し、成功／失敗を分けるdecision graphを組む。特定のp名・d名を使う分岐の特例コードは禁止する。

各更新で検証する新候補は最大128件。順位は `(当該更新のTRAIN検証6例での不一致件数, library+bodyの正準記述長, 正準AST bytes)` の辞書式とし、単位の違うCPUとの加重和にしない。保存64件の上限内で、その6例への不一致を増やさず記述長を短縮するものをcandidateとして保持する。全既観測例での無誤りは保証しない。経験0で発見済みと名乗れないよう、全候補に観測区間digest・生成constructor・依存AST・反例を付す。後の反例で失効させる。

評価時は同じ構文・同じ公開デモの下で最大128候補を調べ、6デモに一致する最小順位の候補を選んでqueryに1回実行する。一致候補がなければABSTAIN。queryの目標・採点で候補選択をしてはならない。候補ごと6デモ×12原子以下、評価queryは12手以下。内部探索も途中・上限・不一致理由を記録する。

これは学習法の具体的な叩き台であり、一般化単一化や候補順の実装詳細は、別の工学PRで正準順序・型規則とともに凍結する必要がある。**旧版提案時点ではbit再現可能な完成アルゴリズムを主張しなかった。-02の全順序・source lockは別添で再固定し、監督者採択前とする**。実装時に都合よく候補を選べないよう、正式評価前に全順序を承認・digest固定する。

STATIC-RANKは旧SPECの特定のFIXED-IF ASTそのものではない。贈与する1分岐scaffoldは明示的な手製の強化であり、FULLと初期在庫が同一とは書かない。同じmeta-runtimeと、同じ最大表現能力の構文・128候補検証上限を使う。これにより、弱い固定列にしか勝たない成功を避ける。順位学習はconstructor／参照項のTRAIN頻度を整数加算し、同点は正準bytes順。FULLだけが内部シミュレーションを無制限に使える構成にしない。

LOOKUPの距離は、6デモの初期／最終状態の固定長符号に対する不一致数＋位置の絶対差とする。各状態をbuffer16枠・clipboard16枠（不足は専用pad）、cursor・anchor・head（noneは専用値）へ符号化し、Sym欄は同一性の不一致、位置欄は差の絶対値（noneとの不一致は16）を加算する。Sym値の大小は使わない。最小距離のTRAIN法則のブロック集合から、同じ状態距離で現在初期状態に最も近い成功traceを選ぶ。同点は公開入力digest順。距離の棄権閾値は設けず、成功traceなしだけABSTAIN。INSERTのSymは記録された観測上の同一位置からの値に限り再束縛を許す。関係述語／分岐graphの生成は禁止。これは表層NNという一方式との比較であり、すべての記憶学習器を代表しない。

全腕で実環境経験・デモ・query・原子意味論・AST上限・queryホライズンは同じ。FULL／STATIC-RANK／LOOKUPの更新はそれぞれ独立、OFFはFULLの複製。CPUや保存形式の完全一致は要求せず、準備費・順位学習・USE費・展開原子数を別掲する。全checkpointをbだけで揃えることで、経験差と内部計算差を混同しない。

## 5. holdoutを正直に保つ最小手順

本案では旧CALのseed／splitを使わず、新しい名前空間 `world-lean-1` を使う。**今回、実seed・実task・target・split manifestは作らない。**

1. 設計採用後・正式評価前に、生成レシピ、上記24/24分割、デモ規則、乱数方式、例数、停止規則、学習／解析ソース、runtime版を1つのmanifestに固定する。UTF-8／LF／key順固定のJSONとSHA-256を使う。循環自己hashは含めず、source commitを外側の記録に結び付ける。
2. 別のEvaluatorプロセスがmaster seedを作り、`SHA256(master || length-prefixed namespace || replicate || phase || law || item)`のcounter streamを使う。整数を剰余にする際はrejection sampling、レシピ・tag・表示改名のstreamを分離。16 replicateは互いに独立なsubstreamとして扱う。学習器にseed、law index、phaseの法則所属を入力しない。
3. holdoutファイルとseedは評価側ディレクトリに置き、学習子プロセスにはpublic仕様例・query初期観測・token集合だけをJSONで渡す。学習実行の入力rootにはholdout／評価ソースを置かず、ネットワーク入口を作らない。module import分離と受渡しschemaのnegative testを別許可の工学工程で確認する。hashは秘匿性や悪意あるコードの隔離を証明しない。
4. 学習を終え、**全seed・全checkpointのsnapshot digestを先に固定**してから評価をまとめて行う。学習器が途中のeval曲線を読んで次checkpointを変える経路をなくす。各評価trialはsnapshotの新しい作業コピー、終了後に作業領域を捨て、成否は親だけが保持する。
5. 実体化時にTRAIN／デモ／queryのmanifest digestを保存する。結果後はseed・必要な原本・snapshotとソース版を監督者へ渡し、同じ結果を再生できるようにする。公開前に学習器が評価答えを読めた場合はSTOP_INVALID。digest不一致も全run停止で、残りのseedだけによる成功認定をしない。

OSのbubblewrapや署名escrowは必須にしない。これは協力的な研究コードの入力分離であり、同一Unixユーザーが意図的に評価側のファイルを開く攻撃に耐える隔離ではない。その強いcustody主張は放棄する（RQ2）。評価ファイルを同じプロセスのglobal変数に置く方式は採らない。

公開の構造分割を学習器開発者が知っていることも限界として開示する。一般アルゴリズムにp／dの特例・test対の対応表を埋め込むことは禁止し、監督者がsourceを確認する。評価後の不具合修正・閾値変更・候補順変更が必要なら、同じholdoutは診断用に降格させ、新版・新seed・新課題で再評価する。数回の同一版byte再生は能力の追加標本に数えない。

## 6. 経験効率の操作化と合格ライン候補

### 6.1 主エンドポイント

seed s・腕 a・checkpoint bで、24法則それぞれ2 queryの成功率を平均した `S[a,s,b]` を得る。FAIL／ABSTAIN／FAULT／12手打切りは0、成功のみ1。分母は予定48 queryで、成功例だけの費用曲線にしない。プロセス事故・ログ欠落は能力失敗と捏造せずrun不完了にし、主推論を保留する。

実際のb幅による台形面積を使う:

`A[a,s] = Σ_k (b[k+1]−b[k]) × (S[a,s,b[k]]+S[a,s,b[k+1]]) / (2×4096)`。

範囲0..1。b=0を含め、完成時点だけの成功率にしない。これは5点間の線形補間によるAULCであり、すべての中間経験点の実測ではない。各対照 cについて `D[s,c]=A[FULL,s]−A[c,s]` を**seed単位**で比較する。48 queryや5 checkpointを独立nへ水増ししない。

主対象は、この固定24未見レシピと均衡query分布に条件付けたseed間の再現性。seedは単なる探索乱数だけでなく、TRAIN初期状態・trace順・表示改名・デモ・queryの実現を引き直す。16 seedから「全法則母集団への信頼区間」を作ったとは言わない。

### 6.2 seed数と計算できる統計

**16 seedを事前固定し、結果による追加・早期有意停止をしない。** FULLと3対照は各seedで同じ入力を使う。16は符号のばらつきを見ながらCPUを抑える妥協。16個中12個でD>0なら、片側二項上側確率は `Σ_(j=12)^16 choose(16,j)/2^16 = 2517/65536 ≈ 0.0384`、13個なら697/65536 ≈0.0106。ゼロ差は非勝利としてn=16の分母に残す保守的な「勝つ確率>1/2」の検定とする。効果量の平均検定とは区別する。

3対照すべてについてこの勝利確率検定を0.05で通すことを**単一の結合した合格**に要求する。どれか1対照に対する帰無が真なら、その対照の棄却が必要なので、このintersection-union判定の全体誤合格率は0.05以下。対照の中から都合のよいp値を選ぶ／個々の比較を別々の確証として売ることはしない。

平均D、中央値、16個の点、全曲線、最終成功率を必ず示す。補助としてseedを丸ごと対応再標本化する9,999回のpercentile bootstrap 95% CIを平均Dに付ける。9999は端点を約250番目の順序統計で示せる軽量な回数。乱数・percentile補間法も固定し、これは小nの近似・各比較の周辺CIであり同時保証ではなく、主合格の救済に使わない。意味法則の独立nとも呼ばない。

16で80%検出力があるとは保証しない。効果が小さければINCONCLUSIVEになることを受け入れる。事前power joint simulation・結果を見たseed増量を行わない。

## 7. 実装形式・再実行一致の範囲

推奨は**CPython 3.12系の特定patchを工程開始前に固定、標準ライブラリのみ、Linux／WSL2の普通のCPU1台、単一worker**。GPU・LLM API・NumPy・コンパイラ・native kernelは不要。既存world_calのimportや改造をせず、将来別package／別CLIにする。人工fixture専用packageとCLIはPR #209で実装済み。本改訂で6デモ依存だけを更新する。

graphは型付きデータASTを信頼されたインタプリタで実行し、eval／exec／任意callbackは不可。候補ランキング・距離・MDLは整数または有理数比較。dict／setの反復順で候補を決めない。Symは値の同一性だけを用い、Unicodeソート順から役割を推定しない。JSONはASCII escapeを固定、UTF-8／LF、辞書key順とリスト順を固定する。

同一source・runtime・入力seed・完了した有限予算の下で、タスク、snapshot、選択AST、行動trace、0/1成否、整数成功数、AULC有理数、二項p値分子分母、固定乱数bootstrapの有理数端点はbyte一致を要求する。wall／CPU／RSS／時刻／絶対パス／OS識別情報は別の非決定的metadataへ分離し、一致対象にしない。グラフ画像や丸めた表示値は判定根拠にしない。

runtimeの異なるpatch／OS間のbyte一致は未検証であり、人工fixtureで確かめるまで保証しない。OS時間capで停止したrunは打切り箇所のbyte一致を要求せず、**完了した科学結果も名乗らない**。同一seed再生は再現性検査であって独立標本の追加ではない。

## 8. 全体計算量の上限と時間案

以下は**設計上限の算術**で、実測ではない。1 candidateのデモ検証を6×12=72原始シミュレーション以下とし、全腕を128候補探索するものとして過大側に数える。LOOKUPの軽さ・OFFの共有・評価cacheは削減に入れない。

| 工程 | 上限算式 | 原子遷移回数上限 |
|---|---|---:|
| 共有TRAIN実経験 | 16×4096 | 65,536 |
| TRAIN候補更新（OFF共有、他3腕） | 16×3×64更新×128候補×6例×12手 | 28,311,552 |
| 主holdoutのデモ検証 | 16×4腕×5点×48 query×128候補×6例×12手 | 141,557,760 |
| 最終の副次48 queryのデモ検証 | 16×4×48×128×6×12 | 28,311,552 |
| 全queryの最終実行 | 16×4×(5×48+48)×12 | 221,184 |
| 48レシピ内の曖昧性監査（主＋副次、1回） | 16×48 query×2種類×48レシピ×(6デモ+1query)×8手 | 4,128,768 |
| 合計 | 上記の和 | **202,596,352** |

TRAIN更新の6検証例は、各新候補について直近の該当6例に限る軽量な提案検査。既保存候補の失効確認は新たなTRAINイベントごとに最大64候補×12手として、さらに **16×4096×66×12=50,331,648** を予約する。全体は **252,928,000遷移以下**に抑える。候補生成・一般化単一化・NN距離計算・JSON保存は遷移数とは別のCPUである。

NNは最大512 trace、各query最大6デモ×2状態×35欄の加算距離で、16×(5×48+48)×512≒236万trace候補距離。law距離の内部比較はデモ6×6組（旧版は4×4組）を要し、CPU外挿にはこの増分を別途含める。文字列の二次時間編集距離は使わず、TRAIN法則ごとのデモ距離はcheckpoint内でcacheする。候補生成は各更新最大1024構文試行で停止し、検証128に入らなかった分も費用に残す。ライブラリ64×32nodeと全TRAIN traceのため、RSSは目安512MiB以内、保存量は目安2GiB以内とする（軽量CPU機を想定するため）。

仮にインタプリタが毎秒2万／1万／5000遷移なら、遷移処理だけ約3.51／7.03／14.05時間。候補構成・ログ等を2倍の余裕込みで約7〜28時間の原子遷移2倍の算術目安（候補構成・LOOKUP距離・ログなどは追加費用）とする。速度の実測がない以上「必ず数時間」とは約束しない。標準1coreでwall上限48時間、全process合計CPU上限36時間。数日を超える探索は行わない。

別許可の工学工程では、公開の人工fixtureだけで10万遷移＋候補更新を測り、少なくとも約5000遷移/秒と構成費が上の余裕に収まるかを確認する。STATIC-RANKについても、人工の入出力例から個々の局所編集・複写・条件付き選択へ128候補内で到達するfixtureを要求し、単に同じgrammarというだけで強い対照と認定しない。失敗時は候補順／予算を正式評価前に再設計し、FULLへ完成解法を移植しない。正式holdoutを使わず全工程を外挿し、48時間内が見込めなければ**正式seed生成前に**新版を提案する。結果を見てseed数を減らして完走扱いにしない。正式runがwall／CPU／保存capを超えたら `RESOURCE_STOP / INCOMPLETE`、未完了seedを取り除いた合格認定は禁止する。

計算量を減らした本質は、48レシピ・128候補・短いホライズン・16 seedへの有限化、snapshotを先に全保存して評価を一括すること、そしてMCによる実験計画そのものの全走査を外したこと。評価結果を見て楽な課題だけ選ぶ削減ではない。

## 9. 三層と段階認定を維持する

| 段階 | 必要な証拠 | 本案での到達範囲 |
|---|---|---|
| 生成 | 空在庫から、観測digestを持つ新しい実行可能ASTが生じる | 正式run後に検証可能。手製レシピ対応や完成Ifの事前在庫なら不成立 |
| 使用 | 同一snapshotのON/OFFで合法な決定が変わる | trace介入で検証可能。ただし変更が有益かは成績との突合が必要 |
| 効率 | 強いSTATIC-RANK・LOOKUP・OFFに対して未見組合せのAULC改善 | 本案の主対象。条件付きのLEAN候補であり最終認定は独立審査 |
| L-Skill | 圧縮されたbodyと費用差 | 副次的に観測可。圧縮だけで概念とは呼ばない |
| L-Concept | 経験から選ばれた関係が予測／行動を改善 | 来歴・反例・使用は監査可。REC等の対照不足により固有帰属は未認定 |
| L-Schema | 新しい述語・下位方策へ再束縛する構造に固有の効用 | **未認定**。PRED-ONLY／macro-only等と新たなholdoutを要する |

三層を単一の成功率で一括認定しない。Bに向けた経験効率が陽性でも、数学的表現力差・一般知能・「Ifを無から発明した」は言えない。

## 10. 陽性・陰性の読み方と縮小キル条件

陽性なら「この既知原子意味論・公開6例・有限構文・未見body対の設計分布に限り、経験由来の表現を使う方式が、指定3対照より訓練実環境経験に対して速く有用になった」と言える。内部計算・人間が設計した特徴・提示例の費用と併記する。別世界・新述語族・一般PC操作・全探索最適性・schema固有性は言えない。

陰性なら、差の符号・CI・失敗群・usageを全件保存し「この方式／予算／分布では実用差を示せなかった」と言える。未見課題の識別不足・候補探索不足・疎い経験が競合原因であり、自律概念学習一般の不可能性とは言えない。p>0.05やCIが0を含むだけでは同等とも言わない。

| キル／停止 | 観測条件 | 次の扱い |
|---|---|---|
| 汚染／比較不正 | target漏洩、snapshot不一致、腕ごとの経験差、生成規則digestずれのいずれか1件 | STOP_INVALID。主推論なし、原因を修正した新版・新holdoutへ |
| 仕様不足 | recipe内AMBIGUOUSが主queryの10%超 | B候補なし。問題提示を考え直す |
| 使用なし | 16中12 seedにusage差がない | 獲得物による効率説明を停止。性能差があっても使用経路を再監査 |
| 固定体系の天井 | STATIC-RANKのb=0平均成功率≥0.90、かつ平均AULC≥0.90 | 機会が小さい有限設定としてこの課題／予算を終了。全空間の飽和証明ではない |
| 実質差が小さい | 全run完了で、STATIC-RANKまたはOFFに対する平均D<+0.05 | この4腕／生成器の路線へseed追加し続けない。方式・課題を考え直す。統計的等価性の認定ではない |
| 有害 | FULL最終成功率が最強対照より5pp超低い、またはFULL最終<0.60 | 有用性なしとして停止し、技能の過一般化／探索費を調べる |

| 資源停止 | 48h wall／36h CPU／2GiB保存上限を超える | RESOURCE_STOP。部分runは診断のみ、合格不可 |

これらは観測後の判定であり、事前に全探索を完成させないと1回も走れないK0機械ではない。事前には、人工fixtureで世界遷移と生成bodyの到達性・no-op・finish規則・入出力分離・空初期在庫を確認するだけとする。その工学確認も本ラウンドでは実行しない。

## 12. 逆質問と採用前の未解決点

次は実装者の推測で埋めず、監督者回答／Owner決定を求める。提案の文書提出は続けるが、未解決のまま凍結・実装へ進まない。

- **RQ1 認定の射程**: 今回は4腕の`LEAN_B_EFFICIENCY_CANDIDATE`までを最初の到達点とし、WORLD-RのL-Schema込みの最終認定Bは後続に残すことでよいか。最初から完全なB認定まで必要なら、LOOKUPをPRED-ONLYへ交換するだけでは記憶対照が消えるため、4腕制限か認定要求のどちらかを再協議する必要がある。
- **RQ2 分離の脅威モデル**: 協力的な研究コードをsource監査し、別process／入力root／schemaでholdoutを学習経路から外す範囲で十分か。悪意ある同一Unixユーザーまで防ぐ保証を要求するなら、本案の簡易分離では足りず、実行基盤確保が別の前提になる。
- **RQ3 goal contract**: 6仕様例つき・問い合わせ0・最終4欄一致・finish時のみ採点する新契約を認めるか。WORLD-Rはtarget漏洩禁止を定めるが、この状態目標と提出方式を一意には定めていない。bufferだけの採点や成功即終了を必須と解釈するなら本案は変更が必要で、推測で互換と扱わない。

6デモの識別性、128候補で固定体系が強い対照になるか、5000遷移/秒の費用見積もりは**未検証の設計リスク**。逆質問への回答と設計採用の後、別許可の人工fixture／TRAIN工学工程で確認し、正式評価ソースと数値を新commitに固定する。ここから重いCALへ戻って無限に完全認証を要求せず、確認できなかった点は主張縮小または新版の理由として残す。
