## 0. Owner 決定済み事項（前提として動かさない）

1. 本軸は実験Aの後継軸として立てる。実験Aは閉じて記録に固定済み
   （G6-4 完了: 方法間の費用優位は観測されず、固定費支配的。
   認定状態は不変のまま終了）。
2. 認定の作法（事前登録・封印・ON/OFF 対照・実測）と工学資産は
   引き継ぐが、実験Aの認定状態は本軸に持ち越さない。
   本軸は独自の主張と認定目標を定義する。
3. 最初の世界は「小さなテキストエディタ世界」とする。
   転移先として「フォーム世界」を第1.5世界に置く。
4. 巨大な事前学習 LLM は初期実験では使わない（従来方針の継続）。
   LLM の常識を借りて一般化する方式は本軸の主張としない。

## 1. 新軸の主張（監督者案・Owner 採用済み）

固定された操作族の中で解法を見つけるのではなく、有限な世界での
経験の蓄積から、述語・技能・条件分岐を含む操作言語をシステム
自身が拡張できるか。そしてその拡張が、未見の課題・未見の世界
への転移として測れるか。

基本ループ（想定）:
経験の蓄積 → 族の不十分さの検出（点火） → 新しい記号／操作の提案
→ 圧縮・予測・転移による検証 → ライブラリへの採用 → 次の経験へ。

## 2. 最初の世界 v0（監督者案の輪郭）

- 状態: 小さい文字集合上の文字列バッファ、カーソル位置、
  選択範囲、クリップボード。全て記号として観測可能。
- 行動: 原子操作のみ（挿入・削除・カーソル移動・選択・複写・貼付等）。
  検索置換のような出来合いの技能は与えない。
- 課題族: 転写（逐次）／パターン複写（繰り返し）／
  内容依存の編集（条件分岐）／2段階の合成課題（技能の連結）。
- 成功判定: 世界の外にある決定的な検証器（目標バッファとの一致等）。
- 転移試験: 文字集合の改名、文字列長の一般化、
  フォーム世界（入力欄＝同じ編集操作＋ポップアップ＝条件分岐）。

## 3. 監督者の暫定方針（PW）

- PW1: 記号・技能は人間が意味のある名前で与えず、システムが
  経験から発見する。内部記号は OP_17 のような無意味な名前でよい
  （2026-11-07 の ChatGPT 回答の核心を本軸でも維持する）。
- PW2: 技能への昇格基準は頻度だけにしない。MDL（記述長）＋
  状態予測誤差＋実行コストの複合で判定する。
- PW3: 主評価は転移と経験効率（解けるまでに要した経験回数）。
  費用は記録するが主評価にしない（実験Aの教訓: 小規模では
  固定費が支配的で方法間の差が潰れる）。
- PW4: 「条件分岐が育った」の判定は二階で測る。特定の述語に
  対する個別規則（一階）ではなく、新しい述語・新しい行動の
  組み合わせに再学習なしで適用できる型（スキーマ）として
  獲得できたかを、未見の組み合わせで試験する。
- PW5: 課題の生成側を使う場合（Self-Play 的構成）、生成側は
  「同定利得」（その経験で仮説空間がどれだけ絞れたか）で採点し、
  自己ループ内の上達だけでは能力を認定しない。
- PW6: 一般化はカテゴリや常識を与えて行わせない。共通項は
  システム自身が経験の比較から見出すことを主張の中心に置く
  （FLEX への対抗ではなく、その「自力版」を問う）。
- PW7: 世界・課題の多様さへの配分は設計変数として明示する。
  同じ課題の反復より多様な変種が転移を生む可能性（HALO の
  環境多様さスケーリング）を、規模を落として検証対象にする。

## 4. 質問（QW）

- QW1 主張と認定: 「操作言語が成長した」とは何が観測できたら
  言えるか。ライブラリ学習（DreamCoder 等）との差分は何か。
  反証可能な認定目標の定義案を示してほしい。
- QW2 世界 v0 の仕様: 原子操作の最小集合は十分か。文字集合の
  大きさ、バッファ長、選択とクリップボードの要否を含め、
  小さすぎて発見が起きない／大きすぎて帰属が曖昧、の
  境界をどう置くか。
- QW3 課題族の設計: 条件分岐族で「無条件方策の天井」を
  どう保証するか。課題生成の文法と、封印する未見組み合わせ
  （述語×行動×対象）の切り分け方。
- QW4 経験収集: 学習前の経験はどう集めるか。ランダム探索、
  台本、自己生成課題の配分。生成側を同定利得で採点する
  仕組み（PW5）は具体化できるか。経験ログの形式
  （観測・行動・状態変化・成否）の最小仕様も示してほしい。
- QW5 記号・技能の発見: 軌跡の分節化と技能への昇格の手続き。
  引数の抽出、失敗による記号の意味・文法の改訂はどう行うか。
  PW2 の複合基準は実装可能な形に落とせるか。

- QW6 If の獲得: 条件分岐を「型」として獲得させる表現形式。
  一階の個別規則で止まったことと、二階のスキーマが育った
  ことを、実験でどう区別するか（PW4 の試験設計の具体化）。
- QW7 族の不十分さの検出: この世界で「今の表現では足りない」
  ことをシステムが検出する操作的定義。予測誤差の頭打ちか、
  記述長の増大か、それ以外か。誤検出（足りているのに
  新記号を作る）をどう抑えるか。
- QW8 転移とゲート: 改名・長さ一般化・フォーム世界転移の
  各試験で、転移率と経験効率のどの水準を合格線の候補に
  できるか。また、本軸が失敗だったと判断すべき結果
  （キル条件）は何か。
- QW9 共通項の自力発見: 編集行為の列の中から、課題を跨ぐ
  共通構造（例: 選ぶ→変える→確定する、という型）を、
  カテゴリを与えずにシステムが見出せるか。偶然や暗記による
  見かけの共通項とどう区別するか。
- QW10 多様さの配分と連結: 課題の変種の多様さと反復の
  配分をどう設計するか。連結課題（前段の終了状態が次段の
  初期状態になる）で分布がずれる失敗をどう扱うか。
- QW11 将来への接続: 本軸の知見は、実 PC 操作ログからの
  記号生成（預かり中の具体化案）へどう接続するか。
  逆に、エディタ世界で得られても実アプリへは運べない
  ものは何か。Minecraft・実アプリ等の後段の世界の
  位置づけも含めて答えてほしい。
