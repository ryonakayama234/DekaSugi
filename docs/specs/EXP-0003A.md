## 目的・完了の定義
既存の型付き文字列DSLの範囲で、WAKE経験→SLEEP技能候補→DREAM反証練習→固定方策→独立評価の**一周期**を設計し、未知課題での候補探索・正確性・CPU費用を比較する。技能候補生成と新原始演算の獲得は区別する。方法の数値・seed・採否は[plan-v1](../../experiments/EXP-0003A/plan.md)が正本。

## 主要API（形状案、実装はPR 2/3以降）
- `wake(task: TaskSpec, audit: PrivateAudit) -> WakeEpisode`: public taskから探索、独立auditの採点、trace記録。戻り値は学習側に公開・監査情報を分離して渡す。
- `sleep(episodes: Sequence[WakeEpisode]) -> tuple[SkillProposal,...]`: successのみを既存`discover_skills`で処理し、候補body/型/hash/依存/来歴を検査。
- `dream_pool(seed_manifest) -> Sequence[DreamCase]`: 正解を生成可能な固定テンプレートと3例から問題を作る。未承認primitiveの**学習器/実行Registryへの登録・実行**は禁止。OOD参照正解はtrusted generatorだけで計算し、DSLの機能とは数えない。
- `select_dream_cases(pool, positive_wake_features, strategy) -> Sequence[DreamCase]`: family数一致、random/nearest比較、事後結果の条件付き選別は禁止。
- `train_policy(wake_observations, dream_observations, candidate) -> CycleSnapshot`: 各arm独立の版付きhash付学習結果。
- `evaluate(snapshot, private_final) -> EvaluationEvidence`: 事前登録の全条件を独立試行。FINALレコードを上流へ戻さない。
- `project_console(episodes, proposals, dream_cases, evidence) -> ResearchView`: provenance/ref/statusだけをread-only表示し、判定はサーバー側の正本を参照。

## ID-v1 and deterministic selection (PR1 reproducibility gate)
- 公開`TaskSpec.task_id`は、順序付き公開2例+固定domain/schema/limitsのみからcanonical JSON/UTF-8/SHA-256で作る`t-<64hex>`。KernelとSkill discoveryにはこれだけを渡す。
- generator/evaluatorのsource IDは`train|dev|final|dream-fNN-iNNN`ではなく**`<split>-fNN-iNNN`**形式（例: `train-f00-i000`, `dream-f04-i007`）で、private manifestに隔離。`pool_id`はdream source IDと一致、arm別`dream_case_id`は`b2:`/`b3:`を付与する。
- 同距離5NNは公開`task_id`のASCII辞書順、同距離のB3 poolは`pool_id`のASCII辞書順、B2はfamily index順の固定seed shuffleと選択順を保持。選択済みID順序とpool入力hashをsnapshotで追跡する。
- ID衝突・公開task重複・manifest hash不一致はfail closed。参照例・詳細ハッシュ仕様は[plan-v1 ID-v1](../../experiments/EXP-0003A/plan.md)。

## PR2 TRAIN-only implementation boundary (Issue #32)
- `packages/exp0003a`は事前登録された8 family×20件のTRAIN生成器と不透明公開task ID、評価者専用の`TrainCase`（family/seed/private auditはKernelへ渡さない）を実装。`--mode train`以外のCLI経路は存在しない。
- `wake()`: 既存`bounded_synthesize`/SEC-004による公開2例の探索を1回だけ実行し、その選択解法を独立第三例で1回だけ監査。別々のprimitive meterとCPU/wallを保存。監査不合格は再探索も成功扱いもしない。
- `WakeEpisode`は公開task ID、program AST、探索traceと費用、private auditの**判定とhash参照のみ**を含む。監査入力/出力、family、split、seedの生値は含まない。
- `sleep()`: 監査器がWAKE直後に確定した`WakeReceipt`とエピソード本文（AST hash/trace/監査判定を含む）の厳密照合を必須にする。監査器の原本を持たない自己申告hashでは承認しない。照合後`WakeEpisode`内の監査成功解法から既存`_subexpressions`/`_operation_ids`規則のまま共通部分ASTを抽出。`discover_skills(tasks)`による再探索やgenerator正解programの取り込みをせず、最低2課題のdistinct provenanceを確認。ランキング先頭1件だけ`candidate`、他は`withheld`。将来のB1/B2/B3向け**proposalのみ**。
- TRAIN証拠は公開run JSONとエピソードJSONLのほか、実際に評価した非公開第3例/生成元/公開TaskSpec/原本receiptを評価器用の別Artifact内ファイルで保全する。公開リポジトリ上のArtifact自体が外部から非公開という意味ではない。
- TRAIN runはエンジニアリング証拠であり、DreamやFINALの成功の証拠ではない。実装ログは[run index](../../experiments/EXP-0003A/runs/README.md)を参照。

## PR3 TRAIN/DREAM policy implementation (Issue #34 / PR #35)
- `packages/exp0003a/pr3.py`はPR2の独立監査済WAKE原本から最上位1件の型付き`SkillCandidate`を再構成し、技能本体を変更せず、各TRAIN160件でOFF/ONそれぞれ独立の公開探索と第三例auditを実施。`PairedObservation`は公開TaskSpecの8D特徴・真の候補数・primitive回数・監査付き正誤のみ。generatorのfamily/seed/audit例は`features`・`choose`の入力ではない。
- DREAM poolは固定seed/文字集合で8×64=512、TRAINとの公開ID・出典ID・seed衝突を拒否。B2は`random.Random(510000000+family_index).shuffle(range64)`の結果先頭12、B3は監査正解かつON primitive回数がOFFより少ないTRAIN正例の8D近傍距離を基準に各family12。距離同点はpool ID辞書順。独立第3例で選別済みケースをOFF/ON評価するまで正誤・費用は教師データに使わない。正例0件ならfail closed。
- 同一技能・同じ既存`features(TaskSpec)`・共通5NN閾値でB1=TRAIN160、B2=TRAIN160+無作為96、B3=TRAIN160+近傍96の`ArmSnapshot`をそれぞれ不変SHA256で保全。`choose()`は公開2例のみから意思決定、誤監査の危険近傍をOFF veto。EXP-0002B凍結実装と標準Registryは変更しない。
- PR3 CLIは`--mode train-dream`のみ。公開run JSONと評価器専用元データ（512プール、private audit、paired探索/監査/trace/原本receipts）の別Artifactファイルを上書き禁止で保存。TRAIN/DREAMエンジニアリングでありH2/H3評価ではない。EXP-0003A DEV/FINAL実行経路はない。

## 禁止事項
- 既存`DEFAULT_PRIMITIVES`変更、runtime任意Python、未レビューmacroの正式登録、EXP-0002Bの凍結method/FINAL112再利用。
- `TaskSpec`にsplit/family/seed/audit/正解変換名を追加してKernelへ渡すこと。
- Dream由来の問題だけをFINALとして採否判定すること。
- 低いASTノード数を原始演算コストの削減と偽ること。
- UIで「採用」「発明」「汎化」などの状態を証拠より先に付与すること。

## エラーと停止
重複task ID / split seed衝突 / スキーマ未知 / hash不一致 / 非信頼Registry / 候補ゼロ / unsafe body / 反証対象正例ゼロ / FINAL誤起動はfail closed。工学的な不具合が研究方法を変える必要を生む場合は**新versionの人間合意まで停止**。
