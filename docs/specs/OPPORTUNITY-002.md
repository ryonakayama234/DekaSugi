## Frozen present-day implementation boundaries
- Primitive order in [library](../../packages/library/__init__.py): `trim`, `lower`, `upper`, each unary `String -> String`. The frozen approved top skill is `skill_8fe1361cb5014f85` with two primitive calls `lower(trim(Input))`; reconstruct/check the actual pinned body hash before any *future* real comparison, not from the name alone.
- [Enumerator](../../packages/synthesis/__init__.py) yields breadth-first by *syntactic* node count, including `Input`, in registry order; it performs no semantic pruning. [Bounded evaluator](../../packages/evaluation/__init__.py) checks *expanded primitive* AST size before charging a candidate, with maximum 4 nodes and 100 evaluated candidates in frozen PILOT-V1.
- OFF exhaustive structural candidate count at maximum expanded size 4: `1+3+9+27=40`. ON with exactly the above single length-two macro and the three primitive operations: `1+4+15+27=47` structural candidates grouped by syntactic AST node layer, after expanded-size filtering (see independent decomposition below). Thus both have fewer than 100 **eligible** candidates; candidate-number exhaustion cannot explain a complete `not_found` in this specific grammar/budget. Candidate *order* and the first public-example matching program may differ, and budget/other operation costs can still matter.
- The exact ON count is `1 + 3 + (9+1) + (27+6) = 47`, grouped by **expanded** primitive call count 0,1,2,3, not by syntax depth. A single macro at a position consumes two primitive calls, so at 2 calls: one macro plus nine primitive sequences; at 3 calls: 27 primitive sequences plus six placements of one macro next to one primitive. Two macros cost four primitive calls and exceed the limit. This is a *structural analytic prediction*, **not** a tested or independently verified measurement; PR2 must compute it independently and fail on discrepancy.
- Macro expansion is semantics-preserving only for a trusted pure typed body, with the exact canonical Python string semantics and no hidden state/side effects. Recheck source/registry trust rather than treating a metadata hash as executable authority.

## Formal proof obligations (PR2, independent reviewer required)
**P1 — conservative representation extension.** Let G0 be the set of all primitive-only syntactic programs with expanded node count <=4, and G1 the set using the same primitives plus one allowed flat macro whose body is lower(trim(Input)), with **expanded** node count <=4 and syntactic depth <=4. Define E to substitute the macro body and preserve composition. Prove by structural induction that E(G1) is a subset of G0. Every G0 program is already available syntactically in G1 (since expanded size implies syntax size <=4), so **E(G1)=G0 as syntactic primitive-expanded programs**. Semantic function equality is the corollary. This says nothing about order, runtime overhead, unknown families, larger budgets, nested macros or future DSLs.
**P2 — independent finite accounting.** A standalone PR2 enumerator **must not call** `enumerate_candidates`, `bounded_synthesize`, the scorer or historical generators to derive the 40/47 oracle. Check both candidate sets and the expansion preimages; semantic duplicates must not be deduplicated to invent distinct function counts.
**P3 — search-order counterexample.** At syntactic candidate budget 5 and max expanded nodes 4, the ON macro `lower(trim(x))` is considered fifth, whereas OFF's primitive-only equivalent is sixth (with current declaration order). For example, entirely invented public examples `('  RED  ', 'red')` and `('  BLUE  ', 'blue')` reject the earlier identity/trim/lower/upper candidates and OFF's fifth `trim(trim(x))`; ON's fifth derived macro matches, whereas OFF's sixth `lower(trim(x))` is excluded at budget 5. PR2 must verify these program positions independently. Verify complete earlier-candidate exclusion before accepting. This budget intervention is a separate synthetic calibration, not a change to frozen 4/100 experiments.
**P4 — expression invariant.** Prove a bounded-domain negative using exact `str.strip/lower/upper` semantics. For example, over a restricted lowercase ASCII alphabet with nonspace input, no program built from these operations can reverse a non-palindromic string. For inserting 'Z' from an input lacking z/Z, case operations cannot create the required letter (unless altered premises apply). Treat broad `reverse_ood` or `replace_first_ood` failure as *diagnostic only* absent explicit domain premises and independent invariant proof.

## Hypotheses / falsifiable claims
| ID | Hypothesis | Evidence that would refute or limit it |
|---|---|---|
| H1 | Frozen primitive-only macros do not expand the 4-node representation set | Independently reproducible counterexample to E(G1)=G0 with a valid trusted program and identical limits |
| H2 | Macro changes syntactic enumeration/order and can alter budgeted accessibility/cost | Independent enumerator cannot reproduce proposed order/cost mechanism |
| H3 | Public-example ambiguity can cause different selected programs and different third-audit success | Constructed examples, strict limits and trusted independent audit fail to exhibit the predicted selection difference; lack of a construction remains `inconclusive` |
| H4 | Kernel action regret and insufficiency of admissible public information are distinct | A claimed information-impossibility case is resolved using exactly the predeclared public representation with no additional information |
| H5 | A failure may be representational, search-limited, or generalization-limited | Classification relies only on `not_found` without a proof/exhaustive oracle, or uses private labels as policy features |

L0/L1 diagnosis cannot by itself establish H3/H4 in a fresh population; H3/H4 need new preregistered stimuli and proper policy/frozen information boundaries.

## Decision theoretic boundary
For paired tasks x, define `a_OFF(x),a_ON(x)` from **independently audited** third-example correctness. Define paired accuracy effect as the empirical mean of `a_ON-a_OFF` over *all valid pairs*. Among both-correct cases define `d_cost = primitive_calls_OFF - primitive_calls_ON`; retain neither-correct cost in the all-task cost budget. Accuracy opportunity = ON-only or OFF-only; unique cost opportunity = both-correct with unequal cost. A `policy_error` is defined only where a uniquely preferred action under preregistered lexicographic objective (audited correctness first, then canonical verifier calls) exists; report denominators per type, not 0/N over ineligible tasks. Report both chosen-action regret and retrospective best-of-two; the latter is a non-executable upper envelope.

The Kernel sees a **frozen function of public TaskSpec only** (at minimum existing 8D features and no evaluator-only data); raw task ID or additional public context must be declared. An evaluator grouping having identical *entire permissible observation* but opposing best actions gives an impossibility witness for deterministic policies under that observation. An 8D feature collision alone demonstrates a limitation of the current feature map, **not** public-information impossibility. Full Bayes-optimal policy value outside a known synthetic finite support is unknown; no oracle label is passed to Kernel.

Learning plasticity is a separate causal contrast: `S_before` vs `S_after` on fresh independent tasks with explicit experience intervention, matched budgets and stored state. This PR1 does **not** estimate that contrast. Human-inserted new primitives are an expressivity control, not autonomous skill invention.

## Future C-G2 outcome semantics — valid generalization error is NOT integrity failure

**Prospective only; unimplemented, not a change to OPPORTUNITY-001.** The existing OPPORTUNITY-001 `packages/evaluation/opportunity_actual.py::normalize_audited_trial()` deliberately throws when its legacy `audit_invalid_solved/false_solved` flag is true. Its strict original security/stop contract remains byte-for-byte immutable. **Do not reuse that normalizer or reinterpret the old flag** in an OPPORTUNITY-002 C-G2 scorer; doing so would censor the very first-solution generalization failures that C-G2 tries to observe.

For a separately versioned, independently reviewed future OPPORTUNITY-002 evaluator, specify two orthogonal fields **before** choosing new task seeds or scoring:

| New-study evaluator outcome (proposed) | Trust/normalization gate | Scientific treatment |
|---|---|---|
| `public_found_audit_correct` | Exact selected program verifies against both public examples, then independently matches private third example | Valid audit-correct outcome |
| `public_found_audit_incorrect` | Same *valid* public verification, selected public-matching program independently **fails** trusted private third-example audit | **Valid generalization failure**, `audited_correct=false`; NEVER alias to legacy `false_solved` |
| `public_not_found` | Reviewed search stops at predeclared budget with no public-matching program; provenance/trace still valid | Valid unsolved/search outcome; audit-correct false, mechanism separately counted, **not** an observed first-solution generalization miss |
| `integrity_invalid` | Any public-verifier inconsistency, program/trace/source/version mismatch, trusted audit label-vs-raw contradiction, evidence tamper or provenance failure | **HARD STOP**; excluded from paired scientific denominator and recorded as invalid, not a regular model error |
| `not_observed` | Missing audit/arm/trace or incomplete task | Exclude as missing with reason and per-arm / paired accounting; never impute false |

The new adapter must check that public verification and canonical selected AST agree, independent audit value and its label agree, and source/sha/policy/skill/meter/chronology locks match **before** assigning a valid outcome. No evaluator-only field may enter the pretrial Kernel choice. These statuses are **proposed schema labels**, not actual existing runtime capabilities or permission to score.

For C-G2, additionally report `n_both_public_found` and `n_discordant_private_audit_given_both_public_found` alongside `n_paired_valid`, `n_public_not_found`, `n_not_observed` and `n_integrity_invalid`. If no both-public-found pairs exist, first-solution generalization is `not_estimable` rather than 0/N. Count public-not-found separately from generalization failures; do not select a new population using post hoc third-audit outcomes. **C-G2 is synthetic-only until** a distinct prospectively frozen adapter, negative tests for valid audit failure vs safety failure, independent source-first review, private third-audit custody and one-shot permission exist.

## Technical and trust decisions
- Use Python 3.12+, stdlib `unittest/itertools/json/hashlib` and existing typed AST/TaskSpec, MetricSpec and EvidenceEnvelope where applicable. No new neural stack, external solver, database or GPU for this finite grammar.
- New versioned `ContrastSpec` is **analysis metadata**, not an executable command; schema described in [ARCH-002](../architecture/contracts.md). An optional `BoundaryCertificate` holds domain premises/logic/source hashes/proof status and reviewer.
- Evaluator-only provenance, third audits, family/seed/source_record_id and scoring labels stay out of Kernel/learner, public GitHub, public Actions artifacts and logs. The policy's decisions are sealed **before** OFF/ON scoring; source-first bytes and immutable access-controlled pretrial private originals must be independently verifiable for any future live trial.
- CI for OPPORTUNITY-002 changes: documentation checks and newly invented synthetic-only fixtures. No new true TRAIN/DEV/FINAL score. Existing unrelated historical CI has main-push DEV smoke; **do not merge this or future PR while that unsafe inherited workflow/source-lock interaction remains unresolved by separately reviewed safe action**. Never weaken old source locks to make a PR green.
- PR1 docs only. PR2 pure analyzer/synthetic verification in a **separate reviewed PR**. Future real trials require a new method version, frozen distribution, independently reviewed source and explicit once-only activation; PR1/PR2 merging never authorizes them.

## Decision outputs and stop conditions
Statuses: `IDENTIFIABLE` (prediction/contrast feasible within declared assumptions), `STRUCTURALLY_UNIDENTIFIABLE` (a reviewed impossibility argument), `INCONCLUSIVE` (missing, inadequate power, unresolved), `INVALID` (trust/source/schema breach). Never silently turn unknown or `false_solved` into a negative or a zero. An engineering PASS proves calibration only, not scientific benefit. Freeze source/method before any real outcomes and stop on leak/duplicate/crash/inconsistent hash/mismatched action source, recording incomplete trials without rerunning.
