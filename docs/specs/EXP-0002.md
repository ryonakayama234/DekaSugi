## 目的と仮説
[Issue #5](https://github.com/ryonakayama234/DekaSugi/issues/5) の一部を実装する。EXP-0001の成功ASTから同一部分式を発見し、候補技能として登録し、同族の未知入力を含む保留課題で探索効率と悪化の両方を測る。[事前登録計画](../../experiments/EXP-0002/plan.md)の閾値は実装前にコミット済み。

## 実装API
- `discover_skills(TRAIN)`: distinct task_idから共通の長さ2以上のunary subtreeを発見。hashごとに集計し、決定的なIDとprovenanceを付す。
- `validate_skill(candidate)`: body、hash、依存関係、来歴、型、既存opとの衝突を検査。
- `registry_with_skill(candidate)`: 元レジストリにmacroを末尾で追加した**新規レジストリ**を作る。DEFAULT_REGISTRYを汚染しない。
- `bounded_synthesize(task, registry, learned)`: ASTノード数をmacro展開後に数え、固定された探索予算で照合する。結果は既存の `SearchResult`。
- `run_experiment()`: TRAINから候補を発見し、DEV・HOLDOUTに対してfixed baselineとcandidate registryを比較する。
- `python -m packages.evaluation --output .run/EXP-0002-result.json`: 実験runを生成。

## Safety / non-goals
- macro bodyに任意Pythonを許可しない。元の純粋なDSL interpreterだけを呼び出す。
- 出典は成功した訓練エピソードのtask_id。入力例そのもの・Web知識・LLMはmacro提案の根拠に用いない。
- 使用可能な3 primitiveのため、抽出は部分式の構造的反復。**普遍的な概念発明や領域間転移の証明ではない**。
- 構造圧縮は原始的実行コストの減少を意味しない。
- 候補が評価ゲートを通過しても、レビューと採用記録なしにはdefault libraryへ昇格しない。

## Review remediation / nested macro cost accounting

GitHub PR #6 review found that a previously learned macro could be referenced in another candidate body, bypassing the intended expanded primitive AST cost bound. Registration now explicitly rejects existing derived operations in skill bodies. Recursive `expanded_nodes` rejects cycles and measures nested expansion safely if invoked, and evaluation checks that macro IDs match the provided metadata. EXP-0002 continues to allow only flat macros. Review and CI verification are required before merging. The preregistered task partitions and acceptance thresholds are unchanged.

## Registered macro / policy-metadata consistency

Macro search is rejected if supplied expansion metadata does not hash to the precise macro body recorded in the registry's `derived-<sha256>` semantics version. Verification occurs **before evaluating candidates**, and the macro body must be primitive-only and type valid. This addresses the second independent review finding on PR #6 without altering preregistered acceptance rules or the historical run.

## 第3回P1レビュー: Registry偽装の封じ込め

[新しいP1レビュー](https://github.com/ryonakayama234/DekaSugi/pull/6#discussion_r4367347313)は、macroの`semantics_version`を通常演算風に偽装して既存ノード予算をすり抜ける経路を指摘した。評価器は固定された3つのprimitiveと実装の同一性を検査し、macro実行系を検証済みASTから再構築するよう修正した。これにより呼び出し元Registryの未検証callbackを実行しない。
