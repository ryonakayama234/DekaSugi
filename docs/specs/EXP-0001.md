# EXP-0001 — Typed program synthesis baseline specification

id: EXP-0001
status: accepted
updated: 2026-10-24
tags: synthesis, specification, interpreter, baseline

## 目的
小規模な文字列操作DSLと決定的な候補列挙器を**外部の学習済みモデルなし**で実装し、少数の入出力例を満たす式を探索できる最小の研究装置を作る。
能力向上はこの実験の主張ではない。改善の主張は後続EXP-0002で評価する。

## 最小構成
- 入力: `TaskSpec v0`（文字列→文字列、複数の入出力例、探索上限）。
- 使えるもの: 入力ノード、`trim`（両端空白除去）、`lower`（小文字変換）、`upper`（大文字変換）の純粋関数。将来の型拡張を見越して型情報を持つ。
- 候補: 入力ノードおよび原始操作を適用した型付きAST。許可されたノード数以下のみ列挙。
- 探索: ノード数の昇順、同値ノードの処理順を固定。候補は構造ハッシュで重複除去。
- 実行: 許可された関数だけ評価するインタプリタ。例外・予算超過は失敗と記録。
- 出力: 発見したAST、全例への適合、候補数、経過時間、終了理由。

## インターフェース（提案）
```text
synthesize(task: TaskSpec, primitives: Registry) -> SearchResult
evaluate(program: TypedAST, input: String) -> String
verify(program: TypedAST, examples: list[Example]) -> Verification
```

## 受入条件
- 例 `"  RED " → "red"`, `" Blue  " → "blue"` を満たすASTを探索する。
- 単純な `trim` のみ、`lower` のみ、恒等変換も、それぞれ正しく探索できる。
- 型不一致AST、登録外演算、無限探索を拒否する。
- 同じ入力・同じ設定なら候補探索順と解法ASTが一致する。
- 不可能課題/極小探索予算では明示的な `not_found` / `budget_exhausted` を返す。
- 依存ライブラリ最小、CPU実行、単体テスト・CLI再実行手順・測定ログを備える。
- 仕様・ARCH-001/002・実験run記録・資料目録を実装PRで同期する。

## 技術的採用判断（EXP-0001 baseline）

事前登録7/7、単体テスト18/18、同条件での再現性、予算・不正ASTの停止性をGitHub Actions上で確認。初回runの記録は [RUN-001](../../experiments/EXP-0001/runs/20261024-0423-9cfb4c1.md)。**固定DSLの非学習ベースラインとして採用**する。第三者査読と、新しい技能による成績向上の検証は未実施。

- `python -m packages.cli --suite --output /tmp/exp0001.json`: 事前登録7ケース、同条件2回試行の再現性チェック。
- `TaskSpec / Program` の正確な形式は [ARCH-002](../architecture/contracts.md)。
- 実験結果と採否は [runs](../../experiments/EXP-0001/runs/README.md) に分けて保存する。実装済みは能力向上の証明ではない。
