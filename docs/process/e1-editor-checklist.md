[配布HTML](../../packages/draft_editor/editor.html)と[仕様](../specs/E1-DRAFT-EDITOR.md)。Windows＋Edgeが主、Galaxy Tab A9+＋Chromeが副。下記は**確認手順**であり、実施済み記録ではない。Muse VMのCodex CLI委任は使わない。

## 起動

1. GitHubのHTMLファイルのRaw表示からファイルとして保存する（GitHubのコード表示そのものはエディタではない）。`editor.html`を決めたフォルダに置き、Edgeで開く。
2. 「ブラウザ内退避が使えます」を確認する。使えない場合も架空文のJSON往復はできるが、通常保存と同等には扱わない。
3. 左下の種別を「動作確認の架空文」にしてから「新しい下書き」を押す。個人的な文はまだ入れない。
4. Androidではファイルのプレビューアでなく実際のChromeでJSが動くことを確認する。開く・保存・読込みが不便／不可能ならそこで止め、端末・ブラウザ・起動方法・症状を返す。PCでの合格をAndroidの合格にしない。

HTMLの置き場所やブラウザを変える前にJSONを出す。同じブラウザ内保存が別のファイルやURLから見えるとは仮定しない。ファイルが自動的に同期されることもない。

## Ownerの5〜10分確認

| 手順 | 操作 | 判定 |
|---|---|---|
| 1 | 「今日は資料を確認します。」をIMEで確定。次の変換を途中で取り消す。既存語の再変換も操作可能なら試す | 確定文が二重に記録されず、中止で本文が壊れず、未確定候補が履歴へ残らない |
| 2 | 範囲を選んで「明日は」へ変更。改行＋「確認👍🏽」を貼付け、undo/redo | 本文と履歴の前後差分が合う。履歴表示で元の入力欄が変わらない |
| 3 | 「保存して区切る」→「この版をJSONに書き出す」 | 区切り状態とファイル書出し要求が別表示。端末の保存先で実ファイルを確認 |
| 4 | タブを閉じ、同じHTML・同じブラウザで開く。続いてJSONを読込む | DBからの復元とJSONからの別コピー復元を別々に確認。原記録は上書きされない |
| 5 | 架空draftコピーを履歴ごと削除 | 対象コピーが消える。書出しファイル・他コピーは残る。負担は許容できるか一言 |

検証できないIME操作は「検証不能（その端末の操作非対応）」として残す。通常確定・訂正・保存往復が失敗したら実用利用へ進まない。通常操作ごとにgapが出る場合も修復対象。画面やログを返す場合も本文・削除履歴を無断で含めず、基本は次の結果票だけでよい。

```text
対象: Windows+Edge / Galaxy Tab A9+Chrome
ブラウザ版 / IME名（分かる範囲）:
起動: file / loopback URL
確定・中止・再変換: PASS / FAIL / 未実施 / 検証不能（理由）
範囲置換・改行・絵文字・undo/redo:
DB再起動復元 / JSON別コピー復元:
gapの有無と操作 / 負担の可否:
```

## Museの独立確認

Draftの正確なhead・HTMLのSHA256・ブラウザ版・起動方式を記録する。人工例だけで、core/browser検査、保存失敗注入・二重タブ競合・不正JSON・削除・CSPと通信を確認する。DOMでcompositionイベントを合成する検査は**実IME確認ではない**。実画面のないVMではIMEの確定／中止／再変換は検証不能とする。

file起動は初期HTML読込み以外のネットワーク要求ゼロ、loopback起動は初期HTMLのGET以外ゼロを点検する。HTMLの禁止されたfetchを試す場合のCSP失敗と、実際に送信された要求を混同しない。ブラウザ自身のサービスは別範囲。

## 利用開始後

工学確認を経てから別日に3件程度の普段の下書きに使う。毎日の課題・投稿・細かい注釈は不要。JSONを読み戻せることと負担を確かめる。入力がない場合はE1未達または縮小判断として返し、件数のための作文を宿題にしない。E2の自動候補提示は別GO。
